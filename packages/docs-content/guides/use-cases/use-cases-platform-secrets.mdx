# Migrate to Platform Secret Stores

For six destinations — Doppler, Infisical, Azure Key Vault, Vercel, Heroku, and Railway — evnx generates CLI commands you review and run. None of these destinations need evnx to hold platform credentials; evnx only knows your `.env` file. Printing the commands does not need the platform's CLI installed either; you need it only to run them.

## Saving and running the commands

By default evnx prints the commands between status lines and a summary. To save them, or pipe them into a shell, add `--print-only`: stdout then holds only the commands, and everything else goes to stderr.

```bash
evnx migrate --to heroku --heroku-app my-app --print-only > heroku-upload.sh

cat heroku-upload.sh     # read it
bash heroku-upload.sh    # run it
rm heroku-upload.sh      # it holds every value
```

Without `--print-only`, `> file` saves the status lines too, and `| bash` hands them to the shell as commands: depending on the destination, it stops at a syntax error before anything runs, or runs the commands and then fails on the lines after them. Earlier versions of this page piped and saved without the flag. Even with it, prefer a file to a pipe: in `… | bash`, any command that reads its standard input would also read the rest of the script.

<Callout type="warning">
  <strong>The commands contain your secret values.</strong> Every destination on this page prints each value inside its command, in single quotes. Delete a saved script once it has run, and never commit it.
</Callout>

A few options work the same for every destination:

- `--env-name production` reads `.env.production` instead of `.env`; `[defaults] env_name` in `.evnx.toml` applies too. The first line names the file read: `✓ Loaded 1 secret from .env.production`.
- `-q` hides the destination's status lines, leaving the commands and the summary.
- Two names that would become one — through `--strip-prefix` or `--add-prefix`, or in Azure Key Vault, which ignores case — are an error, exit 2, naming both. `--allow-collisions` keeps the last value instead and says so on stderr.

## Doppler

Doppler stores secrets in projects and configs. evnx generates one `doppler secrets set` command per variable.

### What evnx generates

```bash
doppler secrets set DATABASE_URL='postgres://user:pass@host:5432/db'
doppler secrets set STRIPE_SECRET_KEY='sk_test_example'
doppler secrets set REDIS_URL='redis://localhost:6379/0'
```

`--project` adds `--project`, and `--doppler-config` adds `--config`. Either works on its own:

```bash
doppler secrets set --project myapp --config prd DATABASE_URL='postgres://user:pass@host:5432/db'
```

Without them, the commands name no project or config, so run them in a directory where `doppler setup` has selected both.

### Requirements

- Doppler CLI installed: [docs.doppler.com/docs/cli](https://docs.doppler.com/docs/cli)
- Logged in (`doppler login`) and a project already created in the Doppler dashboard

### Usage

```bash
# No flags — for a directory set up with `doppler setup`
evnx migrate --to doppler

# Named project and config
evnx migrate \
  --to doppler \
  --project myapp \
  --doppler-config prd \
  --exclude "*_LOCAL"
```

```bash
# Save and run
evnx migrate \
  --to doppler \
  --project myapp \
  --doppler-config prd \
  --print-only > doppler-upload.sh && bash doppler-upload.sh
```

### After migration

Replace your `.env`-based start command with `doppler run`:

```bash
# Before
node server.js

# After
doppler run -- node server.js
```

## Infisical

Infisical works like Doppler from evnx's perspective — one `infisical secrets set` command per variable.

### What evnx generates

```bash
infisical secrets set DATABASE_URL='postgres://user:pass@host:5432/db'
infisical secrets set STRIPE_SECRET_KEY='sk_test_example'
infisical secrets set REDIS_URL='redis://localhost:6379/0'
```

`--project` adds `--projectId`, and `--infisical-env` adds `--env`. Either works on its own:

```bash
infisical secrets set --projectId abc123 --env prod DATABASE_URL='postgres://user:pass@host:5432/db'
```

### Values evnx refuses

A value that is empty, or that starts with `@`, cannot be passed to `infisical secrets set` as written. evnx names every such key and prints nothing (exit 2):

```text
✓ Loaded 3 secrets from .env
Error: these values cannot be passed to `infisical secrets set` as they are:
  SSH_KEY: starts with `@` — read as a file path under `infisical login`, sent as written with a token
  FEATURE_FLAG: empty — infisical rejects an empty value

Set them in Infisical directly, or leave them out with --exclude. Nothing was printed.
```

### Requirements

- Infisical CLI installed: [infisical.com/docs/cli/overview](https://infisical.com/docs/cli/overview)
- Logged in (`infisical login`) and a project created in the Infisical dashboard

### Usage

```bash
evnx migrate \
  --to infisical \
  --project abc123 \
  --infisical-env prod \
  --exclude "*_LOCAL,*_TEST"
```

### After migration

```bash
infisical run -- node server.js
```

## Azure Key Vault

Azure Key Vault stores secrets individually, and does not allow underscores in secret names.

### What evnx generates

evnx converts every `_` to `-` in key names and prints one `az keyvault secret set` per variable:

```bash
# Note: underscores in keys are converted to hyphens for AKV compatibility

az keyvault secret set --vault-name my-vault --name DATABASE-URL --value 'postgres://user:pass@host:5432/db'
az keyvault secret set --vault-name my-vault --name STRIPE-SECRET-KEY --value 'sk_test_example'
az keyvault secret set --vault-name my-vault --name REDIS-URL --value 'redis://localhost:6379/0'
```

It also prints a rename log so you can see which keys were changed:

```text
Key renames applied:
  DATABASE_URL → DATABASE-URL (underscores → hyphens)
  STRIPE_SECRET_KEY → STRIPE-SECRET-KEY (underscores → hyphens)
  REDIS_URL → REDIS-URL (underscores → hyphens)
```

With `--print-only`, the rename log goes to stderr with the other status lines.

<Callout type="warning">
  <strong>Key names are transformed.</strong> Any code that reads <code>DATABASE_URL</code> from your .env must be updated to read <code>DATABASE-URL</code> from Key Vault, or use an alias/mapping layer in your application.
</Callout>

Key Vault also ignores case, so `API_TOKEN` and `api_token` would be one secret there. evnx refuses the pair rather than drop one value:

```text
✓ Loaded 2 secrets from .env
Error: these names become the same name in Azure Key Vault, and one value would be lost:
  API_TOKEN, api_token
  (Azure Key Vault treats names that differ only in case as one name.)
Rename one in the .env, or pass --allow-collisions to keep the last value. Nothing was printed or sent.
```

### Requirements

- Azure CLI installed: [learn.microsoft.com/cli/azure/install-azure-cli](https://learn.microsoft.com/cli/azure/install-azure-cli)
- Logged in (`az login`)
- A Key Vault already created in your subscription

### Usage

```bash
# In a terminal, evnx asks for the vault name
evnx migrate --to azure-keyvault

# Non-interactive
evnx migrate \
  --to azure-keyvault \
  --vault-name my-vault \
  --exclude "*_LOCAL"
```

Without a terminal, a missing `--vault-name` is an error (exit 2).

```bash
evnx migrate \
  --to azure \
  --vault-name my-vault \
  --print-only > azure-upload.sh && bash azure-upload.sh
```

### Minimum permissions

The user or service principal running the commands needs:
- `Key Vault Secrets Officer` role on the vault — for creating and updating secrets
- Or `Key Vault Contributor` at the resource group level

## Vercel

Vercel stores environment variables per project and environment. evnx generates one `vercel env add` command per variable, piping the value in on stdin.

### What evnx generates

```bash
printf '%s' 'postgres://user:pass@host:5432/db' | vercel env add DATABASE_URL production --force --yes
printf '%s' 'sk_test_example' | vercel env add STRIPE_SECRET_KEY production --force --yes
printf '%s' 'redis://localhost:6379/0' | vercel env add REDIS_URL production --force --yes
```

With `--vercel-project my-project`, each command also carries `--project my-project`:

```bash
printf '%s' 'postgres://user:pass@host:5432/db' | vercel env add DATABASE_URL production --project my-project --force --yes
```

`--force` replaces a variable that already exists, and `--yes` skips Vercel's interactive prompt, so a script runs without stopping. All variables go to the `production` environment; evnx has no option for another one.

<Callout type="info">
  <strong>Changed in 0.10.10.</strong> Earlier versions printed <code>--project-id</code>, which the Vercel CLI does not have. Generate any saved script again.
</Callout>

### Requirements

- Vercel CLI installed: `npm install -g vercel`
- Logged in (`vercel login`)
- Project linked (`vercel link`) or `--vercel-project` supplied

### Usage

```bash
evnx migrate \
  --to vercel \
  --vercel-project my-project \
  --exclude "*_LOCAL,*_TEST"
```

### After migration

```bash
# Verify secrets were set
vercel env pull .env.local

# Redeploy
vercel --prod
```

## Heroku

Heroku uses config vars (environment variables) set per app. evnx generates a **single bulk `heroku config:set`** command — one command triggers one dyno restart, rather than one restart per variable.

### What evnx generates

```bash
heroku config:set --app my-app \
  DATABASE_URL='postgres://user:pass@host:5432/db' \
  STRIPE_SECRET_KEY='sk_test_example' \
  REDIS_URL='redis://localhost:6379/0'
```

### Requirements

- Heroku CLI installed: [devcenter.heroku.com/articles/heroku-cli](https://devcenter.heroku.com/articles/heroku-cli)
- Logged in (`heroku login`)
- App already created

### Usage

```bash
# In a terminal, evnx asks for the app name
evnx migrate --to heroku

# Non-interactive
evnx migrate \
  --to heroku \
  --heroku-app my-app \
  --exclude "*_LOCAL,*_TEST"
```

Without a terminal, a missing `--heroku-app` is an error (exit 2).

```bash
evnx migrate --to heroku --heroku-app my-app --print-only | bash
```

### After migration

```bash
# Verify
heroku config --app my-app

# The dyno restarts automatically after config:set
```

## Railway

Railway stores environment variables per project, environment and service. evnx generates a single `railway variable set` command.

### What evnx generates

In a directory linked with `railway link`, the command names nothing else:

```bash
railway variable set \
  DATABASE_URL='postgres://user:pass@host:5432/db' \
  STRIPE_SECRET_KEY='sk_test_example' \
  REDIS_URL='redis://localhost:6379/0'
```

`--railway-project` adds `--project`, and must come with `--railway-environment`, which adds `--environment` — the Railway CLI asks for the environment whenever a command names the project. `--railway-service` adds `--service` and is optional:

```bash
railway variable set --project my-project-id --environment production --service api \
  DATABASE_URL='postgres://user:pass@host:5432/db' \
  STRIPE_SECRET_KEY='sk_test_example' \
  REDIS_URL='redis://localhost:6379/0'
```

`--railway-project` without `--railway-environment` is an error (exit 2):

```text
Error: --railway-project needs --railway-environment: Railway asks for the environment whenever a command names the project.
  evnx migrate --to railway --railway-project <ID> --railway-environment production
  Or leave both out and run the command in a directory linked with `railway link`.
```

<Callout type="info">
  <strong>Changed in 0.10.10.</strong> Earlier versions printed <code>railway --project … variables set</code>, which the Railway CLI cannot parse, and had no <code>--railway-environment</code> or <code>--railway-service</code>. Generate any saved script again.
</Callout>

### Requirements

- Railway CLI installed: `npm install -g @railway/cli`
- Logged in (`railway login`)
- Project linked (`railway link`), or `--railway-project` with `--railway-environment` supplied

### Usage

```bash
# In a directory linked with `railway link`
evnx migrate --to railway

# Named project and environment
evnx migrate \
  --to railway \
  --railway-project my-project-id \
  --railway-environment production \
  --exclude "*_LOCAL"
```

### After migration

```bash
# Verify
railway variable list
```

Setting variables triggers a deploy of the service. To set them without one, add `--skip-deploys` to the printed command.

## Choosing the right platform

| If you want… | Use |
|-------------|-----|
| A dedicated secret manager with audit logs and role-based access | Doppler or Infisical |
| Azure infrastructure already in use | Azure Key Vault |
| Frontend / serverless deployments on Vercel | Vercel |
| Existing Heroku application | Heroku |
| Railway-hosted services | Railway |
| Full cloud provider integration (IAM, KMS) | AWS or GCP (see separate guides) |

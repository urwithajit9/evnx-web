# Convert reference

Every `evnx convert` format with the output it prints, the order in which flags apply,

## Processing pipeline

Every format goes through the same steps, in this order:

```text
.env file
    │
    ▼
Parse                              (order of the file is kept)
    │
    ▼
--include / --exclude              (globs on the names in the .env; exclude wins)
    │
    ▼
--prefix, then --transform         (rename every key)
    │
    ▼
the format's own naming            (gcp: lowercase, _ → -; azure: _ → -; terraform: lowercase)
    │
    ▼
collision check                    (two names → one: exit 2, or --allow-collisions)
    │
    ▼
--base64                           (encode every value)
    │
    ▼
the format's layout                → stdout, or --output FILE
```

**What follows from the order:**

- Filters match the names in your `.env`, before any renaming: `--include "APP_*"`
  still matches `APP_PORT` when `--prefix "MYAPP_"` is set.
- `--prefix` comes before `--transform`: `PORT` with `--prefix "app_"` and
  `--transform camelCase` becomes `appPort`.
- The collision check sees the final names, including the format's own renaming, and
  for Azure Key Vault and GitHub it ignores case as they do.
- If nothing is left after the filters, evnx stops with exit `2` unless `--allow-empty`.

## Format reference

The samples use this `.env`:

```env
DATABASE_URL=postgres://user:pass@localhost:5432/mydb
APP_PORT=3000
APP_DEBUG=false
```

### `json`

```bash
evnx convert --to json
```

```json
{
  "DATABASE_URL": "postgres://user:pass@localhost:5432/mydb",
  "APP_PORT": "3000",
  "APP_DEBUG": "false"
}
```

A flat object of strings, in the order of the file.

---

### `yaml` (alias: `yml`)

```bash
evnx convert --to yaml
```

```yaml
DATABASE_URL: postgres://user:pass@localhost:5432/mydb
APP_PORT: '3000'
APP_DEBUG: 'false'
```

Values YAML would read as a number or a boolean are quoted, so they stay strings.

---

### `shell` (aliases: `bash`, `export`)

```bash
evnx convert --to shell
```

```bash
#!/bin/bash
# Generated by evnx

export DATABASE_URL='postgres://user:pass@localhost:5432/mydb'
export APP_PORT='3000'
export APP_DEBUG='false'
```

Single-quoted: `source <(evnx convert --to shell)` sets each value exactly, and nothing in
a value runs.

---

### `aws-secrets` (aliases: `aws`, `aws-secrets-manager`)

```bash
evnx convert --to aws-secrets
```

```json
{
  "DATABASE_URL": "postgres://user:pass@localhost:5432/mydb",
  "APP_PORT": "3000",
  "APP_DEBUG": "false"
}
```

The same bytes as `json`: the key/value JSON that `aws secretsmanager create-secret
--secret-string` stores as one secret. evnx does not run `aws`:

```bash
evnx convert --to aws-secrets | \
  aws secretsmanager create-secret \
    --name prod/myapp \
    --secret-string file:///dev/stdin
```

---

### `gcp-secrets` (aliases: `gcp`, `gcp-secret-manager`)

Needs `--project`.

```bash
evnx convert --to gcp-secrets --project acme-prod
```

```bash
#!/bin/bash
# Upload secrets to GCP Secret Manager
# Project: acme-prod
#
# Creates each secret, or adds a new version when it already exists.

upsert_secret() {
  if gcloud secrets describe "$1" --project=acme-prod </dev/null >/dev/null 2>&1; then
    gcloud secrets versions add "$1" --data-file=- --project=acme-prod
  else
    gcloud secrets create "$1" --data-file=- --project=acme-prod
  fi
}

printf '%s' 'postgres://user:pass@localhost:5432/mydb' | upsert_secret database-url
printf '%s' '3000' | upsert_secret app-port
printf '%s' 'false' | upsert_secret app-debug
```

One secret per variable. Each value reaches `gcloud` on stdin (`--data-file=-`), byte
for byte — `printf '%s'` adds no newline. Names are lowercased with `-` for `_`; GCP
also allows uppercase and `_`, but these are the names every earlier script created.

---

### `azure-keyvault` (aliases: `azure`, `azure-key-vault`)

Needs `--vault-name`.

```bash
evnx convert --to azure-keyvault --vault-name acme-kv
```

```bash
#!/bin/bash
# Upload secrets to Azure Key Vault
# Vault: acme-kv

az keyvault secret set --vault-name acme-kv --name DATABASE-URL --value 'postgres://user:pass@localhost:5432/mydb'
az keyvault secret set --vault-name acme-kv --name APP-PORT --value '3000'
az keyvault secret set --vault-name acme-kv --name APP-DEBUG --value 'false'
```

Key Vault names allow letters, digits and `-`, so `_` becomes `-`. They also ignore
case: `A_B` and `a_b` would be one secret, which evnx refuses (see
[Names that collide](/guides/commands/convert#names-that-collide)). `secret set` creates
or updates. The value is on the command line while `az` runs.

---

### `github-actions` (aliases: `github`, `gh-actions`)

```bash
evnx convert --to github-actions
```

```text
Paste these into Settings → Secrets and variables → Actions:

Name: DATABASE_URL
Value: postgres://user:pass@localhost:5432/mydb
---
Name: APP_PORT
Value: 3000
---
Name: APP_DEBUG
Value: false

(3 secrets total — paste each one individually)
```

Text for a person to paste into the web form. GitHub stores secret names in uppercase,
so names that differ only in case collide.

---

### `docker-compose` (aliases: `docker`, `compose`)

```bash
evnx convert --to docker-compose
```

```yaml
environment:
  - "DATABASE_URL=postgres://user:pass@localhost:5432/mydb"
  - "APP_PORT=3000"
  - "APP_DEBUG=false"
```

An `environment:` block to place under a service in `compose.yaml`. Each item is
quoted, and a `$` in a value is written `$$` so Compose does not interpolate it.

---

### `kubernetes` (aliases: `k8s`, `kubectl`)

Needs `--name`; `--namespace` is optional.

```bash
evnx convert --to kubernetes --name myapp-env
```

```yaml
apiVersion: v1
kind: Secret
metadata:
  name: myapp-env
type: Opaque
stringData:
  DATABASE_URL: "postgres://user:pass@localhost:5432/mydb"
  APP_PORT: "3000"
  APP_DEBUG: "false"
```

`stringData:` holds the values as they are; Kubernetes encodes them on apply. With
`--base64` the values are encoded and the field is `data:`:

```bash
evnx convert --to kubernetes --name myapp-env --namespace prod --base64
```

```yaml
apiVersion: v1
kind: Secret
metadata:
  name: myapp-env
  namespace: prod
type: Opaque
data:
  DATABASE_URL: "cG9zdGdyZXM6Ly91c2VyOnBhc3NAbG9jYWxob3N0OjU0MzIvbXlkYg=="
  APP_PORT: "MzAwMA=="
  APP_DEBUG: "ZmFsc2U="
```

Referencing a value from a pod:

```yaml
env:
  - name: DATABASE_URL
    valueFrom:
      secretKeyRef:
        name: myapp-env
        key: DATABASE_URL
```

---

### `terraform` (aliases: `tf`, `tfvars`)

```bash
evnx convert --to terraform
```

```hcl
# Generated by evnx

database_url = "postgres://user:pass@localhost:5432/mydb"
app_port = "3000"
app_debug = "false"
```

A `.tfvars` file with names lowercased, for `-var-file` or auto-loading. `${` and `%{`
in a value are escaped, so Terraform does not interpolate them. Your module declares a
`variable` for each name it uses:

```hcl
variable "database_url" { type = string }
variable "app_port"     { type = string }
```

### `doppler` — experimental

```bash
evnx convert --to doppler
```

```json
{
  "DATABASE_URL": {
    "computed": false,
    "value": "postgres://user:pass@localhost:5432/mydb"
  },
  "APP_PORT": {
    "computed": false,
    "value": "3000"
  },
  "APP_DEBUG": {
    "computed": false,
    "value": "false"
  }
}
```

stderr says:

```text
! doppler output is experimental: `doppler secrets upload` is documented to take flat JSON (what --to json prints), not this shape.
```

To import into Doppler, use `--to json` with `doppler secrets upload`.

### `heroku`

Needs `--heroku-app`.

```bash
evnx convert --to heroku --heroku-app acme-web
```

```bash
#!/bin/bash
# Heroku Config Vars
# Generated by evnx
#
# Usage:
#   bash heroku-config.sh
#
# Or set variables individually:
#   heroku config:set KEY=VALUE --app acme-web

set -e

echo "Setting Heroku config vars..."

heroku config:set DATABASE_URL="postgres://user:pass@localhost:5432/mydb" --app acme-web || echo "Failed to set DATABASE_URL"
heroku config:set APP_PORT="3000" --app acme-web || echo "Failed to set APP_PORT"
heroku config:set APP_DEBUG="false" --app acme-web || echo "Failed to set APP_DEBUG"

echo "✓ Config vars set successfully"

# Verify settings:
# heroku config --app acme-web
```

One `heroku config:set` per variable, and Heroku restarts the app after each. `evnx
migrate --to heroku` sets them all in one call.

| Variable | Values | Effect |
|----------|--------|--------|
| `NO_COLOR` | any | Disables colour in evnx's own lines |

The interactive format menu needs a terminal: without one, give `--to`, or the run
exits `2`. evnx does not read `CI`.

## Troubleshooting

### Unknown format

```bash
evnx convert --to k8s-secret
```

```text
✗ Unknown format: k8s-secret

Supported formats:

  Generic:
    json, yaml, shell

  Cloud providers:
    aws-secrets, gcp-secrets, azure-keyvault

  CI/CD:
    github-actions

  Containers:
    docker-compose, kubernetes

  Infrastructure:
    terraform

  Secret managers:
    doppler (experimental), heroku, vercel (experimental), railway (experimental)

  Aliases:
    k8s → kubernetes, tf → terraform, yml → yaml
    gh-actions → github-actions, compose → docker-compose
```

**Fix:** use a name or alias from the list (`kubernetes`, `k8s`); case does not matter.

---

### A format needs a name

```text
Error: --to gcp-secrets needs --project: the Google Cloud project the secrets go to. Nothing was printed.

  evnx convert --to gcp-secrets --project <PROJECT>
```

**Fix:** pass the flag it names: `--project` (gcp-secrets), `--vault-name`
(azure-keyvault), `--heroku-app` (heroku), `--name` (kubernetes). Each is checked by
that platform's naming rules:

```text
Error: --heroku-app "acme web" is not a valid name here.

Expected 3–30 lowercase letters, digits and dashes, starting with a letter and not ending with a dash. Nothing was printed or sent.
```

---

### Input file not found

```bash
evnx convert --to json --env .env.production
```

```text
Error: .env.production does not exist

Create it with `evnx init`, or point at another file with --env.
```

**Fix:** pass the right `--env` path, or `--env-name production` to pick
`.env.production` from the current directory.

---

### Nothing left to convert

```text
Error: --include/--exclude left nothing to convert — all 9 variable(s) were filtered out.
  Check the patterns: they are case-sensitive globs matched against variable names.
  Pass --allow-empty to write the empty output anyway.
```

**Cause:** the patterns matched no name — often a case mismatch (`aws_*` does not match
`AWS_REGION`) or a pattern without a wildcard (`AWS` matches only a variable named
exactly `AWS`).

**Fix:** correct the pattern (`--include "AWS_*"`), or pass `--allow-empty` when an
empty result is expected. An empty `.env` gives `… holds no variables, so there is
nothing to convert.` and the same fix.

---

### Two names become one

```text
Error: these names become the same name in azure-keyvault, and one value would be lost:
  A_B → A-B, a_b → a-b
  (azure-keyvault treats names that differ only in case as one name.)
Rename one in the .env, or pass --allow-collisions to keep the last value. Nothing was written.
```

**Fix:** rename one of them in the `.env`, drop the `--transform` that merged them, or
pass `--allow-collisions` to keep the last value. evnx then names the one it kept on
stderr.

---

### `--prefix` refused

```text
Error: --prefix "APP-" is not a valid name here.

Expected a letter or `_`, then letters, digits and `_`, so every name stays a variable name. Nothing was printed or sent.
```

**Fix:** use letters, digits and `_` (`--prefix "APP_"`). A target's own naming, such as
Key Vault's `-`, is applied by the format.

---

### Prefix and transform give an unexpected name

With `--prefix "app_"` and `--transform camelCase`, `PORT` becomes `appPort`, not
`app_PORT`. The prefix is added first, then the whole name is transformed:

```text
PORT
→ app_PORT     (after --prefix "app_")
→ appPort      (after --transform camelCase)
```

For `APP_PORT`, use `--transform uppercase`.

# evnx convert

`evnx convert` reads a `.env` and prints it in the format one of 14 targets expects:
JSON, YAML, a shell script, a Kubernetes Secret, a Compose `environment:` block, a
Terraform `.tfvars` file, or the commands or payload for a cloud secret store. It
never contacts the target itself: it writes the artefact, and you run it.

<Prerequisites>
  <Prerequisite href="/guides/getting-started/installation">Install evnx</Prerequisite>
</Prerequisites>

<Callout type="warning" title="Changed in v0.10.9">
  The formats that write a place into their output need it named:
  <code>--project</code> (gcp-secrets), <code>--vault-name</code> (azure-keyvault),
  <code>--heroku-app</code> (heroku), <code>--name</code> (kubernetes). They printed
  <code>my-project</code>, <code>my-keyvault</code>, <code>YOUR_APP_NAME</code> and
  <code>app-secrets</code> for you to edit. A filter that leaves nothing, an empty
  <code>.env</code>, and two names that become one name in the output are now exit
  <code>2</code>; <code>--include</code> takes <code>?</code>, a <code>*</code> anywhere and
  comma lists; an unknown <code>--transform</code> is an error.
</Callout>

---

## Signature

```bash
evnx convert [OPTIONS]
```

Without `--to`, evnx opens a format menu when there is a terminal, and exits `2` naming
`--to` when there is not.

---

## Flags

| Flag | Default | Description |
|------|---------|-------------|
| `--env <PATH>` | `.env` | The file to convert |
| `--env-name <NAME>` | — | Convert `.env.<NAME>` instead. Conflicts with `--env` |
| `--to <FORMAT>` | menu | The output format; see [Formats](#formats) |
| `-o, --output <FILE>` | stdout | Write to `FILE`, readable by you only (`0600`) |
| `--force` | off | Replace `FILE` when it exists. The input is never replaced |
| `--gitignore` | — | Add `FILE` to `.gitignore` without asking |
| `--no-gitignore` | — | Skip the `.gitignore` check for `FILE` |
| `--include <PATTERN>` | all | Keep only names matching a glob; see [Filtering](#filtering) |
| `--exclude <PATTERN>` | none | Drop names matching a glob; exclude wins |
| `--only <WHICH>` | — | **v0.11.0+** — `secrets` keeps only the variables whose name or value says secret (`*_PASSWORD`, a provider key, a URL with a password, …); `public` keeps the rest. Applied with `--include` and `--exclude` |
| `--allow-empty` | off | Convert even when no variable is left |
| `--allow-collisions` | off | When two names become one, keep the last value |
| `--prefix <PREFIX>` | — | Prepend to every name. Letters, digits and `_`, not starting with a digit |
| `--transform <MODE>` | — | `uppercase`, `lowercase`, `camelCase` or `snake_case` (any case) |
| `--base64` | off | Base64-encode every value. For `kubernetes`, writes `data:` instead of `stringData:` |
| `--project <PROJECT>` | — | Google Cloud project. Required by `gcp-secrets` |
| `--vault-name <NAME>` | — | Azure Key Vault. Required by `azure-keyvault` |
| `--heroku-app <APP>` | — | Heroku app. Required by `heroku` |
| `--name <NAME>` | — | The Kubernetes Secret's name. Required by `kubernetes` |
| `--namespace <NAMESPACE>` | — | The Secret's namespace, optional |

`-v` / `--verbose`, `-q` / `--quiet` and `--no-color` are global flags. The converted
output goes to stdout and nothing else does: notices and the `Docs:` line go to stderr,
so a pipe carries the artefact alone.

## Formats

| Format | Aliases | Output | Needs |
|--------|---------|--------|-------|
| `json` | — | flat object, every value a string | — |
| `yaml` | `yml` | mapping, values that look like numbers or booleans quoted | — |
| `shell` | `bash`, `export` | `export NAME='value'` script | — |
| `aws-secrets` | `aws`, `aws-secrets-manager` | the flat JSON `create-secret --secret-string` takes | — |
| `gcp-secrets` | `gcp`, `gcp-secret-manager` | script that creates each secret or adds a version | `--project` |
| `azure-keyvault` | `azure`, `azure-key-vault` | `az keyvault secret set` script, `_` → `-` | `--vault-name` |
| `github-actions` | `github`, `gh-actions` | text to paste into the GitHub web form | — |
| `docker-compose` | `docker`, `compose` | `environment:` list, `$` written `$$` | — |
| `kubernetes` | `k8s`, `kubectl` | `v1` Secret, `stringData:` (or `data:` with `--base64`) | `--name` |
| `terraform` | `tf`, `tfvars` | `name = "value"`, names lowercased | — |
| `doppler` | — | **experimental** | — |
| `heroku` | — | `heroku config:set` script, one call per variable | `--heroku-app` |
| `vercel` | — | **experimental** | — |
| `railway` | — | **experimental**: the same JSON as `json` | — |

[Convert reference](/guides/reference/convert-reference) shows each format's output.

<Callout type="warning" title="Experimental formats">
  The <code>doppler</code>, <code>vercel</code> and <code>railway</code> shapes have not been
  checked against those services' importers, and evnx says so on stderr when you choose
  one. Doppler documents flat JSON for <code>doppler secrets upload</code>, which is what
  <code>--to json</code> prints. Vercel's API takes <code>{"{key, value, type, target}"}</code>
  objects, which this map does not have. Railway documents no import that takes this JSON.
</Callout>

### The names a target needs

A format that writes a place into its output requires the flag that names it, and
checks it by that platform's rules before anything is printed:

```bash
evnx convert --to gcp-secrets
```

```text
Error: --to gcp-secrets needs --project: the Google Cloud project the secrets go to. Nothing was printed.

  evnx convert --to gcp-secrets --project <PROJECT>

No verdict: evnx did not finish. This is not a clean result.
```

A name flag given to a format that does not use it is refused rather than ignored:

```bash
evnx convert --to json --project acme-prod
```

```text
Error: --project is for --to gcp-secrets; --to json does not use it. Nothing was printed.
```

## Transform values

`--transform` renames every key after `--prefix` is added. Case does not matter:
`--transform CamelCase` works.

| Value | Input | Output |
|-------|-------|--------|
| `uppercase` | `database_url` | `DATABASE_URL` |
| `lowercase` | `DATABASE_URL` | `database_url` |
| `camelCase` | `DATABASE_URL` | `databaseUrl` |
| `snake_case` | `DatabaseURL` | `database_url` |

An unknown mode is an error:

```text
Error: unknown transform 'title' — expected one of: uppercase, lowercase, camelCase, snake_case
```

## Filtering

`--include` and `--exclude` take the globs `evnx migrate` and `evnx cloud run` take.
Matching is case-sensitive.

| Pattern | Matches |
|---------|---------|
| `AWS_*` | `AWS_REGION`, `AWS_SECRET_ACCESS_KEY` |
| `*_URL` | `DATABASE_URL`, `REDIS_URL` |
| `DB_*_URL` | `DB_PRIMARY_URL` — a `*` anywhere |
| `APP_?ORT` | `APP_PORT` — `?` is exactly one character |
| `AWS_*,REDIS_URL` | either: a comma list |

Repeat a flag to add patterns (`--include "AWS_*" --include REDIS_URL`). A name
matching `--exclude` is dropped even when `--include` matches it.

When the filters leave nothing, evnx stops rather than print an empty object for a
pipeline to upload:

```bash
evnx convert --to json --include "NOPE_*"
```

```text
Error: --include/--exclude left nothing to convert — all 9 variable(s) were filtered out.
  Check the patterns: they are case-sensitive globs matched against variable names.
  Pass --allow-empty to write the empty output anyway.
```

An empty `.env` is refused the same way. `--allow-empty` converts it to the empty
output and exits `0`.

### Secrets or the rest: `--only`

**v0.11.0+** — split a `.env` by what its variables hold: public values to a build
system, secrets to a secret manager.

```bash
evnx convert --to json --only public   > public.json
evnx convert --to aws-secrets --only secrets
```

A variable is a secret when its **name** says so (`*_PASSWORD`, `*_SECRET`, `*_TOKEN`,
`*_KEY`, …) or its **value** does: a provider key (`sk_live_…`, `ghp_…`), a private key, a
URL with a password in it. From

```text
APP_NAME=shop
PORT=8080
DB_PASSWORD=hunter22hunter
DATABASE_URL=postgres://u:pw@h/db
STRIPE_KEY=sk_live_51H8xQ2eZvKYlo2CpR4mN7bV9
```

`--only secrets` keeps `DB_PASSWORD`, `DATABASE_URL` (its password) and `STRIPE_KEY`;
`--only public` keeps `APP_NAME` and `PORT`. It combines with `--include` and
`--exclude`; when they leave nothing, the error names `--only`.

## Names that collide

Two names can become one name in the output: `Api` and `API` under
`--transform uppercase`, or `A_B` and `a_b` for a format that renames or a target
that ignores case — gcp-secrets lowercases and writes `_` as `-`, terraform lowercases,
and Azure Key Vault and GitHub treat names that differ only in case as one. evnx refuses
rather than lose a value:

```text
Error: these names become the same name in gcp-secrets, and one value would be lost:
  A_B, a_b → a-b
Rename one in the .env, or pass --allow-collisions to keep the last value. Nothing was written.
```

`--allow-collisions` keeps the last value and says so on stderr:

```text
! A_B, a_b → a-b: kept the value of a_b (--allow-collisions)
```

## Writing to a file

`--output` writes the file readable by you only (`0600`). An existing file is refused
without `--force`, and the `.env` being read is never the output, by any name:

```text
Error: --output '.env' is the same file as the env file '.env'. Nothing was written; choose another --output.
```

The file holds every value, so in a git repository evnx checks `.gitignore` for it, the
way [`evnx template`](/guides/commands/template) does. With a terminal it asks; without
one it warns:

```text
✓ Converted successfully
Output written to: secrets.json
! 'secrets.json' may contain secrets and is not in .gitignore
```

`--gitignore` adds the entry without asking, and `--no-gitignore` skips the check.

## Interactive mode

`evnx convert` with no `--to` opens a menu:

```text
Select output format:
> json - Generic JSON key-value object
  yaml - Generic YAML key-value format
  shell - Shell export script (bash/zsh)
  aws-secrets - AWS Secrets Manager JSON (for create-secret --secret-string)
  gcp-secrets - GCP Secret Manager script (gcloud; needs --project)
  azure-keyvault - Azure Key Vault script (az; needs --vault-name)
  github-actions - GitHub Actions secrets (text to paste into the web form)
  docker-compose - Docker Compose YAML environment
  kubernetes - Kubernetes Secret YAML (stringData, or data with --base64; needs --name)
  terraform - Terraform .tfvars file
  doppler - Doppler secrets JSON (experimental)
  heroku - Heroku config vars script (heroku; needs --heroku-app)
  vercel - Vercel environment variables JSON (experimental)
  railway - Railway variables JSON (experimental)
```

Choosing a format that needs a name still needs its flag on the command line. In a
script or CI job there is no menu:

```text
Error: --to is required when there is no terminal to ask.

  Pass one explicitly:
    evnx convert --to <FORMAT>

  Available: json, yaml, shell, aws-secrets, gcp-secrets, azure-keyvault, github-actions, docker-compose, kubernetes, terraform, doppler, heroku, vercel, railway
```

## Exit codes

| Code | Meaning |
|------|---------|
| `0` | Converted |
| `2` | Nothing was converted: an unknown format or flag value, a missing name flag, a missing `.env`, an existing `--output` without `--force`, an output that is the input, names that collide, or no variables left |

`convert` has no findings, so it never exits `1`.

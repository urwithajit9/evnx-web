# evnx diff — Command Reference

Compare `.env` and `.env.example` files to identify missing, extra, and mismatched variables with security-first defaults and predictable output.

<Prerequisites>
  <Prerequisite href="/guides/getting-started/installation">Install evnx</Prerequisite>
</Prerequisites>

<Callout type="info">
  <strong>Security by Default:</strong> Variable values are hidden unless <code>--show-values</code> is explicitly passed, in <em>every</em> format. Credential-shaped keys are masked as <code>***</code> even with <code>--show-values</code> — the flag cannot reveal them. <strong>v0.10.0+</strong>: before that, <code>--format json</code> printed every differing value in full regardless of the flag, and the mask carried the value's first two characters.
</Callout>

---

## Command signature

```bash
evnx diff [OPTIONS]
```

<Callout type="info">
**Comparing two real environments** is usually the diff you want:

```bash
evnx diff --env-name production --against staging
```

The default compares `.env` against `.env.example`, where every correctly filled-in value
shows as "different" — the template holds placeholders by construction, so that column is
noise. Needs **v0.5.0+**.
</Callout>

<Callout type="warning">
`-e`, `-f` and `-r` have been listed on this page as short forms for `--env`, `--format`
and `--reverse`. **They do not exist** — `-i` for `--interactive` is the only short form
`diff` has.
</Callout>

## Options reference

| Flag | Type | Default | Description |
|------|------|---------|-------------|
| `--env` | `path` | `.env` | Path to the active environment file to compare |
| `--env-name` | `string` | — | **v0.5.0+** — Use `.env.<NAME>` instead of `.env`. Conflicts with `--env`; a name whose file does not exist is an error listing the ones that do |
| `--example` | `path` | `.env.example` | Path to the file to compare against |
| `--against` | `string` | — | **v0.5.0+** — compare against `.env.<NAME>`. Conflicts with `--example` |
| `--show-values` | `bool` | `false` | Show values for keys that are **not** credential-shaped. Cannot reveal a credential-shaped key — those are always `***` |
| `--format` | `enum` | `pretty` | Output format: `pretty` (colored terminal), `json` (machine-readable), or `patch` (unified diff) |
| `--reverse` | `bool` | `false` | Reverse comparison direction: compare example → env instead of env → example |
| `--ignore-keys` | `list` | `[]` | Comma-separated list of keys to exclude from comparison (e.g., `DATABASE_URL,REDIS_URL`) |
| `--with-stats` | `bool` | `false` | Include extended statistics in JSON output (`similarity_percent`, `overlap_count`, etc.) |
| `--interactive`, `-i` | `bool` | `false` | Enable interactive merge mode (only applies when `--format patch` is used) |
| `--verbose`, `-v` | `bool` | `false` | Enable detailed debug output to stderr |
| `--help`, `-h` | `bool` | `false` | Display help information |

<Callout type="info">
**v0.5.0+ — the JSON carries a `summary`.** A gate no longer has to fetch three
arrays and add up their lengths:

```bash
evnx diff --format json | jq -e '.summary.missing == 0 and .summary.extra == 0'
```

The counts are derived from the arrays beside them at output time, so they
cannot disagree with them.
</Callout>

<Callout type="warning">
**Gate on `missing` and `extra` — not on `total`.** `total` folds in
`different`, and against a template every filled-in value *is* different by
construction: `.env.example` holds empty placeholders and `.env` holds real
values. So `summary.total` reaches `0` only when the two files carry identical
values, which a real pair never does.

The same arithmetic drives the exit code, so **`evnx diff` exits `1` on a
perfectly healthy project** — see [Exit codes](#exit-codes) below. Use
`--env-name production --against staging` when you want `different` to carry
meaning, or gate on the two structural counts as above.
</Callout>

### Format values

| Value | Output style | Best for |
|-------|-------------|----------|
| `pretty` | Colored terminal output with icons (`+`, `-`, `~`) | Human review, local development |
| `json` | Structured JSON with `missing`, `extra`, `different` arrays | CI/CD pipelines, programmatic consumption |
| `patch` | Unified diff format with `+`/`-` prefixes | Automation, piping to `patch` or scripts |

## Differences the contract explains

**v0.5.0+.** A variable declared `environments = ["production"]` is *supposed* to
be absent from staging. Reporting it as drift is noise:

```console
$ evnx diff --env-name production --against staging
  1 different value  ·  1 explained by [vars] environments: SENTRY_DSN
```

It is named rather than silently dropped — a reader who knows the files differ
needs to see that evnx noticed and had a reason.

This applies only when **both** sides are named environments. `.env.example` is a
template, so an `environments` list has nothing to say about it.

<Callout type="info">
An explained difference does **not** affect the exit code. It is not drift, so a
CI gate will not fail over it — and when it is the only difference, the output
says so rather than claiming the files are identical.

The JSON gains a `by_design` array, omitted when empty, so a consumer written
before v0.5.0 sees the same document.
</Callout>

See [`evnx spec`](/guides/commands/spec) for the contract itself.

## Exit codes

| Code | Meaning | Use case |
|------|---------|----------|
| `0` | ✅ No differences at all — same keys **and** same values | Success in scripts |
| `1` | ⚠️ Differences found (missing, extra, **or** mismatched values) | See the caveat below before gating on this |
| `2` | ❌ Runtime error — file not found via `--env`/`--example`, parse failure, unknown flag | Debug tooling or environment issues |

<Callout type="warning">
**Do not gate CI on `evnx diff`'s exit code.** Code `1` means *any* difference,
including the value differences a template guarantees — so a healthy project
where `.env` is fully populated from `.env.example` exits `1`, every time. The
idiom this page used to recommend,
`evnx diff && echo "in sync" || echo "drift detected"`, reports drift on every
correctly configured repository.

Two things that do work:

```bash
# structural drift only — keys present or absent, values ignored
evnx diff --format json | jq -e '.summary.missing == 0 and .summary.extra == 0'

# or use the command built for gating, which has a three-state contract
evnx sync --check
```

⚠️ **Two further edges.** A non-existent `--env-name` / `--against` target is a
real error but exits `1`, not `2` — indistinguishable from drift by exit code
alone. And on that path `--format json` writes **nothing** to stdout, so a `jq`
consumer receives empty input rather than an error object. Check the JSON
parsed before trusting the verdict.
</Callout>

## Output structure by format

### `pretty` format (default)

Human-readable output with colored status indicators:

```
┌─ Comparing .env ↔ .env.example ─────────────────────┐
└──────────────────────────────────────────────────────┘

Missing from .env (present in .env.example):
  + NEW_FEATURE_FLAG

Extra in .env (not in .env.example):
  - DEPRECATED_VAR

Different values:
  ~ DATABASE_URL
    .env.example: postgresql://localhost:5432/dev
    .env: postgresql://prod-server:5432/prod

Summary:
  + 1 missing (add to .env)
  - 1 extra (consider removing or adding to .env.example)
  ~ 1 different values
```

### `json` format

Machine-readable output for programmatic consumption:

```json
{
  "missing": ["NEW_FEATURE_FLAG"],
  "extra": ["DEPRECATED_VAR"],
  "different": [
    {
      "key": "DATABASE_URL",
      "example_value": null,
      "env_value": null,
      "values_redacted": false
    }
  ],
  "stats": {
    "total_keys_env": 12,
    "total_keys_example": 13,
    "overlap_count": 11,
    "similarity_percent": 84.62
  },
  "summary": {
    "missing": 1,
    "extra": 1,
    "different": 1,
    "total": 3
  }
}
```

<Callout type="info">
  The <code>stats</code> field is only included when <code>--with-stats</code> is passed. Redacted value fields appear when the key matches sensitive patterns.
</Callout>

### `patch` format

Unified diff-style output for automation:

```patch
# Add these to .env:
+ NEW_FEATURE_FLAG=placeholder

# Remove these from .env:
- DEPRECATED_VAR=old_value

# Update these in .env:
- DATABASE_URL=postgresql://prod-server:5432/prod
+ DATABASE_URL=postgresql://localhost:5432/dev
```

## Sensitive key auto-redaction

A key is credential-shaped if its name **contains** any of `PASSWORD`, `PASSWD`,
`PWD`, `SECRET`, `TOKEN`, `API_KEY`, `APIKEY`, `PRIVATE_KEY`, `AUTH`,
`CREDENTIAL` — or **ends with** `_KEY`, `_SECRET`, `_PASSWORD`, `_TOKEN`,
`_PASSWD`.

| Example key | Why |
|---|---|
| `DB_PASSWORD`, `ADMIN_PWD` | contains `PASSWORD` / `PWD` |
| `SECRET_KEY`, `APP_SECRET` | contains `SECRET` |
| `API_TOKEN`, `AUTH_TOKEN` | contains `TOKEN` |
| `AWS_ACCESS_KEY`, `STRIPE_KEY` | ends with `_KEY` |
| `STRIPE_APIKEY` | contains `APIKEY` |
| `RSA_PRIVATE_KEY` | contains `PRIVATE_KEY` |
| `OAUTH_SECRET`, `DB_CREDENTIAL` | contains `AUTH` / `CREDENTIAL` |

<Callout type="warning" title="Three of those rows were wrong until v0.10.0">
`ADMIN_PWD`, `AWS_ACCESS_KEY` and `STRIPE_APIKEY` were listed here as redacted
and **were not**: `PWD` and `APIKEY` were never patterns, and `API_KEY` carries
an underscore that `AWS_ACCESS_KEY` does not have. The table described the
intent; the code did not implement it. All three are matched now.

The suffix rule is deliberately broader than the one `evnx validate` uses for
weak-secret checks. Masking `SECRET_KEY_ROTATION_DAYS` costs a line of
information; printing `SIGNING_KEY` costs the key. `KEY` is a *suffix* rather
than a substring so that `KEYBOARD_LAYOUT` and `MONKEY_COUNT` stay out.
</Callout>

Redaction behaviour:
- **Without `--show-values`**: credential-shaped keys print `***`; every other
  value is withheld entirely. Only key names appear.
- **With `--show-values`**: keys that are not credential-shaped print their
  value. Credential-shaped keys still print `***` — the flag has no power over
  them, in any format.
- **`--format json`**: `example_value` and `env_value` carry only what is safe
  to print, and are `null` when withheld. `values_redacted` tells a mask from a
  literal. **v0.10.0+** — see the breaking-change note below.
- **`--format patch`**: prints real values, because a patch exists to be applied
  and a masked one would write `***` into your file. This is the one format that
  does, and it is reachable only by asking for it.

<Callout type="warning" title="Breaking in v0.10.0: the JSON shape">
`example_value` and `env_value` are now nullable and hold only what is safe to
print. `values_redacted` is new. **`example_value_redacted` and
`env_value_redacted` are gone.**

Holding the raw value beside the mask was the bug: every consumer had to know to
prefer the second, and `--format json` did not — so it printed the secret while
the human output printed the mask. If you parsed `*_redacted`, read
`example_value` / `env_value` instead; if you parsed `env_value` expecting a raw
value, pass `--show-values` and note that credential-shaped keys will be `***`.
</Callout>

## Key order preservation

Output order matches insertion order from the source files (not hash order):

```bash
# .env.example contents (insertion order):
Z_LAST=value
A_FIRST=value
M_MIDDLE=value

# Output shows missing/extra keys in file order:
Missing from .env:
  + Z_LAST
  + A_FIRST
  + M_MIDDLE
```

This ensures predictable, reproducible output for:
- ✅ Code review diffs
- ✅ CI/CD log comparison
- ✅ Automated patch application

## Interactive merge mode (`--format patch --interactive`)

When both `--format patch` and `--interactive` are specified, evnx prompts for selective change application:

```
🔧 Interactive Merge Mode
Prompts: (y)es, (n)o, (s)kip rest

➕ Add NEW_FEATURE_FLAG=placeholder? [y/n/s]: y
   ✓ Queued: + NEW_FEATURE_FLAG=placeholder

✏️  Update DATABASE_URL?
   - postgresql://prod-server:5432/prod
   + postgresql://localhost:5432/dev? [y/n/s]: n
   ✗ Skipped

📋 Applied changes:
  + NEW_FEATURE_FLAG=placeholder

💡 Tip: Save output and apply with: patch -p1 < changes.patch
```

<Callout type="warning">
  Interactive mode only works with <code>--format patch</code>. Other formats ignore the <code>--interactive</code> flag.
</Callout>

## Statistics reference (`--with-stats`)

When `--with-stats` is passed with `--format json`, the output includes a `stats` object:

| Field | Type | Description |
|-------|------|-------------|
| `total_keys_env` | `integer` | Total variable count in the `.env` file |
| `total_keys_example` | `integer` | Total variable count in the `.env.example` file |
| `overlap_count` | `integer` | Keys present in both files |
| `similarity_percent` | `float` | Sørensen-Dice coefficient: `2×overlap / (env + example) × 100` |

Similarity interpretation:
- `100.0`: Files have identical key sets
- `50.0`: Half the keys overlap (e.g., 1 shared key out of 2 total each)
- `0.0`: No keys in common

## Troubleshooting

### "Failed to parse" error
```
✗ Failed to parse .env: Invalid format at line 5: missing '=' separator
```

**Solution**: Check the indicated line for malformed `KEY=value` syntax. Comments (`#`) and blank lines are allowed; `export` prefix is supported.

### No output despite expected differences
```
✓ Files are identical
```

**Check**:
1. Are you comparing the correct files? Use `--env` and `--example` to specify paths explicitly
2. Are keys being filtered by `--ignore-keys`? Remove the flag or verify the key list
3. Is `--reverse` changing the comparison direction unexpectedly?

### Sensitive values still visible in output
```
  + DB_PASSWORD = mysecretpassword123
```

**Solution**:
- Omit `--show-values` to hide all values: `evnx diff`
- Or ensure the key name contains a sensitive pattern: rename `DB_PASSWORD` → `DATABASE_PASSWORD` (still matches)

### JSON output missing `stats` field
```json
{
  "missing": [...],
  "extra": [...],
  "different": [...]
  // stats field absent
}
```

**Solution**: Add `--with-stats` flag: `evnx diff --format json --with-stats`

`evnx diff` answers two questions:

- **Against a template** (the default, `.env` ↔ `.env.example`): which **keys** does
  `.env` lack, and which does the template lack? Values are not compared, because a
  filled-in value differs from its placeholder by design.
- **Between two environments** (`--env-name production --against staging`): which keys
  does one lack, and which **values** differ?

Values are never printed unless you pass `--show-values`, and even then secrets stay
masked. Every output on this page is from evnx 0.10.18.

<Prerequisites>
  <Prerequisite href="/guides/getting-started/installation">Install evnx</Prerequisite>
</Prerequisites>

<Callout type="warning" title="Changed in v0.10.13">
Against a template, `diff` used to compare values too, so every correctly filled-in value
showed as "different" and a healthy project exited 1. Older versions of this page told you
not to gate CI on the exit code for that reason. Since 0.10.13 only key names are compared
against a template: a healthy project exits 0, and the exit code is a gate.
</Callout>

---

## Command signature

```bash
evnx diff [OPTIONS]
```

```bash
evnx diff                                         # keys .env lacks, or the template lacks
evnx diff --fail-on missing                       # fail only when .env lacks a template key
evnx diff --env-name production --against staging # two environments: keys and values
evnx diff --format json | jq -e '.summary.missing == 0'
```

---

## Options reference

| Flag | Description |
|------|-------------|
| `--env <FILE>` | The file on the left. Default `.env`, or `[defaults] env_name` from `.evnx.toml` |
| `--example <FILE>` | The template on the right, compared by key name only. Default `.env.example`, or `[defaults] example` |
| `--env-name <NAME>` | Use `.env.<NAME>` on the left. A name with no file is an error listing the ones that exist; it never falls back to `.env` |
| `--against <NAME>` | Compare against `.env.<NAME>`: keys **and** values |
| `--values` | Compare values against the template too. Expect every filled-in value to be listed |
| `--show-values` | Print values. Secrets stay masked in `pretty` and `json`; see [Values and secrets](#values-and-secrets) |
| `--format <FORMAT>` | `pretty` (default), `json` or `patch`. An unknown value exits 2 |
| `--reverse` | Swap the two sides |
| `--ignore-keys <KEYS>` | Leave these keys out (comma-separated, exact case). Adds to `[diff] ignore_keys` |
| `--fail-on <WHAT>` | What fails the run: `missing`, `extra`, `different`, comma-separated. All three by default |
| `--skip-without-env` | With no `.env`, skip (exit 0) and say so. For pre-commit hooks, not CI |
| `--with-stats` | Add a `stats` object to the JSON. `--format json` only |
| `-i`, `--interactive` | Prompt for each change and write the chosen ones, keeping `.bak` (**v0.11.0+**). `--format patch` only; not with `--reverse` |
| `-v`, `--verbose` | Say what is compared and what fails the run |
| `-q`, `--quiet` | Print nothing when there is nothing to report |

<Callout type="warning">
`-e`, `-f` and `-r` have been listed on this page as short forms for `--env`, `--format`
and `--reverse`. **They do not exist** — `-i` for `--interactive` is the only short form
`diff` has.
</Callout>

## Against a template

```bash
evnx diff
```

```text
  evnx diff  .env ↔ .env.example

Missing from .env (present in .env.example):
  + REDIS_URL

Extra in .env (not in .env.example):
  - LOCAL_DEBUG_MODE

  1 missing from .env  ·  1 not in .env.example
  values not compared against a template (--values to compare them)
```

`+` is a key the left file **lacks**; `-` is a key only the left file has. The run exits
`1`. Once the keys match:

```text
  evnx diff  .env ↔ .env.example

✓ .env and .env.example have the same keys
  values not compared against a template (--values to compare them)
```

and it exits `0`. The header and the last line go to stderr.

### Choosing what fails: `--fail-on`

The report always lists everything; `--fail-on` changes only the exit code. The usual gate
is that `.env` has every key the template declares:

```bash
evnx diff --fail-on missing
```

```text
  evnx diff  .env ↔ .env.example

Extra in .env (not in .env.example):
  - LOCAL_DEBUG_MODE

  1 not in .env.example
  values not compared against a template (--values to compare them)
```

That exits `0`: an extra local key is reported but does not fail. `--fail-on different`
needs values to be compared, so against a template it is refused unless you add `--values`:

```text
Error: --fail-on different needs values to be compared, and against a template diff compares key names only.

Add --values to compare them, or compare two environments with --against NAME.
```

### Comparing values against the template: `--values`

```bash
evnx diff --values
```

```text
  evnx diff  .env ↔ .env.example

Extra in .env (not in .env.example):
  - LOCAL_DEBUG_MODE

Different values:
  ~ DATABASE_URL
  ~ STRIPE_SECRET_KEY
  ~ REDIS_URL

  1 not in .env.example  ·  3 different values
```

Every filled-in value differs from its placeholder, so this is mostly useful to find a
value somebody forgot to fill in: a key that is *not* listed still holds the template's
value.

## Between two environments

```bash
evnx diff --env-name production --against staging
```

```text
  evnx diff  .env.production ↔ .env.staging

Extra in .env.production (not in .env.staging):
  - SENTRY_DSN

Different values:
  ~ DATABASE_URL
  ~ STRIPE_SECRET_KEY
  ~ NODE_ENV

  1 not in .env.staging  ·  3 different values
```

Keys and values are both compared. Which values differ is shown; the values themselves are
not, unless you add `--show-values`:

```text
Different values:
  ~ DATABASE_URL
    .env.staging: postgres://admin:***@db.stg:5432/app
    .env.production: postgres://admin:***@db.prod:5432/app
  ~ STRIPE_SECRET_KEY
    .env.staging: ***
    .env.production: ***
  ~ NODE_ENV
    .env.staging: staging
    .env.production: production
```

## Output formats

### `json`

```bash
evnx diff --format json
```

```json
{
  "schema_version": 2,
  "compared": "keys",
  "missing": [
    "REDIS_URL"
  ],
  "extra": [
    "LOCAL_DEBUG_MODE"
  ],
  "different": [],
  "ignored": [],
  "summary": {
    "missing": 1,
    "extra": 1,
    "different": 0,
    "total": 2
  }
}
```

`compared` is `keys` against a template and `values` with `--values` or `--against`.
Against a template `different` is always empty, so `summary.total` is a usable gate. When
values are compared, each `different` item says what it holds:

```json
{
  "key": "DATABASE_URL",
  "example_value": null,
  "env_value": null,
  "value_state": "withheld"
}
```

`value_state` is `withheld` (no `--show-values`), `masked` (a secret, shown as `***` or
with its password masked) or `shown`.

<Callout type="warning">
**Schema 2 (v0.11.0+).** `values_redacted` is gone and `schema_version` is `2`. Read
`value_state` instead: `value_state == "masked"` is the old `values_redacted == true`.
</Callout>

`--with-stats` adds:

| Field | Type | Description |
|-------|------|-------------|
| `total_keys_env` | `integer` | Keys in the left file |
| `total_keys_example` | `integer` | Keys in the right file |
| `overlap_count` | `integer` | Keys present in both |
| `similarity_percent` | `float` | Sørensen-Dice coefficient: `2×overlap / (env + example) × 100` |

Without `--format json` it is refused, exit 2.

### `patch`

**v0.11.0+** — a unified diff of the left file (`.env`) that `patch -p1` applies:

```console
$ evnx diff --format patch
# LOCAL_DEBUG_MODE is only in .env; this patch keeps it
--- a/.env
+++ b/.env
@@ -2,0 +3,1 @@
+REDIS_URL=redis://localhost:6379
```

```bash
evnx diff --format patch > changes.patch && patch -p1 < changes.patch
```

- **Against a template** it appends the names `.env` is missing, with the template's
  lines. Those are committed placeholders, so the patch prints nothing of `.env`.
- **A key only in `.env` is kept**, and named in a `#` line before the diff, which
  `patch` skips. Nothing is removed.
- **When values are compared** (`--values`, `--against`, `--reverse`) the patch also
  replaces the lines that differ, so it carries real values: it needs `--show-values`,
  and without it the run stops with exit `2` rather than print a patch that would
  write `<withheld>` into your file.
- A value spread over several lines is never half-replaced: the key is named in a `#`
  line, to change by hand.

Before 0.11.0 this printed `# Add these to .env:` / `+ KEY=<withheld>` sections that
`patch` rejected ("Only garbage was found in the patch input").

### `--interactive`

```bash
evnx diff --format patch --interactive
```

Asks about each change in turn, then **writes the chosen ones** to the left file and
keeps the previous file as `.env.bak` (**v0.11.0+**). Values in the questions are
`<withheld>` unless `--show-values`. The exit code is the comparison's, made before the
write.

It needs a terminal; without one it refuses (exit `2`) and names
`evnx diff --format patch`. `--interactive --reverse` is refused too: it would write
`.env`'s values into the committed template. To add names to the template, use
`evnx sync`, which writes placeholders.

## Values and secrets

Without `--show-values` no value is printed, for any key, in any format.

With `--show-values`, `pretty` and `json` still mask secrets, two ways:

- **By name.** A key is a secret if its name **contains** `PASSWORD`, `PASSWD`, `PWD`,
  `SECRET`, `TOKEN`, `API_KEY`, `APIKEY`, `PRIVATE_KEY`, `AUTH` or `CREDENTIAL`, or **ends
  with** `_KEY`, `_SECRET`, `_PASSWORD`, `_TOKEN` or `_PASSWD`. Its value prints as `***`.
  `MY_CUSTOM_SECRET_VALUE` is masked; `KEYBOARD_LAYOUT` is not.
- **By value.** A password inside a URL is masked whatever the key is called
  (`postgres://admin:***@db.internal:5432/app`), and so is a value shaped like a token.

A `patch` that carries values, and `--interactive` with `--show-values`, print exact
values, because their output exists to be applied. Do not run them where the output is
logged.

**v0.11.0+** — a name containing `PUBLIC_KEY` or `PUBLISHABLE_KEY` is not a secret by its
name (`VAPID_PUBLIC_KEY`, `STRIPE_PUBLISHABLE_KEY`); a value shaped like a secret is still
masked.

## Exit codes

| Code | Meaning |
|------|---------|
| `0` | Nothing that `--fail-on` counts. Against a template, by default: the keys match |
| `1` | Differences found that `--fail-on` counts |
| `2` | No verdict: a missing or unreadable file, an unknown `--env-name`, a bad flag, or a refused combination |

The refused combinations are `--with-stats` without `--format json`, `--interactive`
without `--format patch` or with `--reverse`, a `--format patch` that would carry values
without `--show-values`, and `--fail-on different` without values to compare. Each ends
with `No verdict: evnx did not run. This is not a clean result.`

```bash
evnx diff --fail-on missing
case $? in
  0) echo ".env has every key the template declares" ;;
  1) echo "keys missing — see the report" ;;
  2) echo "diff did not run" ;;
esac
```

## In CI and pre-commit

The exit code is the gate:

```yaml
- name: .env.example and the deployed env agree
  run: evnx diff --env-name production --example .env.example --fail-on missing
```

For a pre-commit hook, use the one evnx ships:

```yaml
# .pre-commit-config.yaml
repos:
  - repo: https://github.com/urwithajit9/evnx
    rev: v0.10.18
    hooks:
      - id: evnx-diff
```

Its entry is `evnx diff --fail-on missing --skip-without-env`: the commit is blocked when
`.env` lacks a key `.env.example` declares, extra local keys do not block, and a fresh
clone with no `.env` is skipped rather than failing every new contributor's first commit.

## Ignoring keys

```bash
evnx diff --ignore-keys LOCAL_DEBUG_MODE
```

```text
✓ .env and .env.example have the same keys (1 key ignored)
```

Names are exact case. `--ignore-keys` adds to `[diff] ignore_keys` in `.evnx.toml`, so a
project can ignore a key for everyone. `-v` lists names that matched no key:

```text
⋯ comparing .env (6 keys) with .env.example (5 keys)
⋯ .env.example is a template: key names only (--values compares values)
⋯ fails on: missing, extra, different
⋯ ignored: LOCAL_DEBUG_MODE
⋯ ignore names that matched no key (case counts): NOPE
```

---

## Key order

Keys are listed in the order they appear in the files, not sorted and not in hash order,
so the output of two runs over the same files is identical:

```text
# .env.example contents:
Z_LAST=value
A_FIRST=value
M_MIDDLE=value

# a .env without them reports, in file order:
Missing from .env (present in .env.example):
  + Z_LAST
  + A_FIRST
  + M_MIDDLE
```

## `diff` does not read the contract

A variable declared `environments = ["production"]` in `[vars]` is reported like any other
when it is absent from staging, and it counts towards the exit code. See
[`evnx spec`](/guides/commands/spec) for the contract itself.

## Troubleshooting

### `.env does not exist`

```text
Error: .env does not exist

Create it with `evnx init`, or point at another file with --env.
```

Exit 2. In a fresh clone that is expected: create `.env` from the template with
`evnx sync --direction reverse`. In a pre-commit hook, `--skip-without-env` skips this case.

### `Failed to parse`

```text
Error: Failed to parse bad.env: Invalid format at line 2: missing '=' separator
```

Exit 2. Fix the named line. Comments (`#`), blank lines and an `export` prefix are allowed.

### Every value shows as different

You passed `--values` against a template. That is expected: a filled-in value differs from
its placeholder. Drop `--values`, or compare two environments with `--against`.

### JSON has no `stats`

Add `--with-stats`, together with `--format json`.

# evnx template — Command Reference

Render a configuration file (YAML, JSON, TOML, or any other text) from a template,
filling in values from `.env`. The result holds real values, so evnx creates it
readable by you only and offers to keep it out of git.

<Prerequisites>
  <Prerequisite href="/guides/getting-started/installation">Install evnx</Prerequisite>
  <Prerequisite href="/guides/reference/env-file-syntax">Understanding .env syntax</Prerequisite>
</Prerequisites>

<Callout type="info">
  <strong>When to use this command:</strong> Use <code>evnx template</code> when you need to generate environment-specific configuration files (YAML, JSON, TOML, etc.) from a template, injecting values from your <code>.env</code> file. Ideal for CI/CD pipelines, Docker builds, or multi-environment deployments.
</Callout>

---

## Quick example

```env
# .env
APP_ENV=production
APP_NAME=billing api
DB_HOST=db.internal
DB_PORT=5432
DB_SSL=on
```

```yaml
# config.yaml.template
app:
  env: {{APP_ENV|upper}}
  name: {{APP_NAME|title}}
database:
  host: ${DB_HOST}
  port: {{ DB_PORT | int }}
  ssl: {{DB_SSL|bool}}
  pool: {{DB_POOL|default:10}}
```

In a terminal, evnx asks whether to add the result to `.gitignore`; Enter answers yes:

```console
$ evnx template --input config.yaml.template --output config.yaml

  Generate config from template

✓ Loaded 5 variables from .env
✓ Read template from config.yaml.template
✓ Generated config at config.yaml
'config.yaml' may contain secrets — add it to .gitignore? yes
✓ Added 'config.yaml' to .gitignore
  Docs: https://docs.evnx.dev/cli/commands/template

$ cat config.yaml
app:
  env: PRODUCTION
  name: Billing Api
database:
  host: db.internal
  port: 5432
  ssl: true
  pool: 10

$ ls -l config.yaml | cut -c1-10
-rw-------
```

`DB_POOL` is not in `.env`, so `|default:10` supplied the value.

## Command signature

```bash
evnx template --input <TEMPLATE> --output <OUTPUT> [OPTIONS]
```

### Required arguments

| Argument | Type | Description |
|----------|------|-------------|
| `--input` | `path` | The template to render |
| `--output` | `path` or `-` | Where to write the result. `-` prints it on stdout and writes no file |

### Optional options

| Flag | Default | Description |
|------|---------|-------------|
| `--env` | `.env` | The env file to take values from. Without `--env`, `[defaults] env_name` in `.evnx.toml` applies when it is set |
| `--env-name` | — | Use `.env.<NAME>` instead of `.env`. Conflicts with `--env`; a name whose file does not exist is an error listing the ones that do |
| `--strict` | off | Refuse to write when a placeholder has no value |
| `--dry-run` | off | **v0.10.5+** — render and report what would be written; write nothing |
| `--mkdir` | off | **v0.10.5+** — create the output's missing directories |
| `--mode` | `0600` for a new file | **v0.10.3+** — the output's file mode in octal (`0640`), applied to a new or an existing file |
| `--gitignore` | — | Add the output to `.gitignore` without asking. Conflicts with `--no-gitignore` |
| `--no-gitignore` | — | Skip the `.gitignore` check and its warnings. Conflicts with `--gitignore` |
| `--verbose`, `-v` | off | Verbose output |
| `--quiet`, `-q` | off | Print nothing on success; warnings and errors still print |
| `--no-color` | off | Plain output (as `NO_COLOR` does) |
| `--help`, `-h` | — | Display help information |

<Callout type="warning">
`-i`, `-o` and `-e` have been listed on this page as short forms for `--input`,
`--output` and `--env`. **None of them exist** — `template` has no short forms of its own.
</Callout>

## What gets written

- **A new output is created readable by you only** (`0600`, **v0.10.3+**). Pass
  `--mode 0640` to choose another mode.
- **An existing output is replaced** and keeps its mode. evnx says `Replaced app.conf`,
  and warns when that mode lets other users read it:

  ```text
  $ evnx template --input in.tmpl --output app.conf --no-gitignore
  ...
  Replaced app.conf
  ! app.conf is readable by other users (mode 640); evnx keeps the mode you set
       →  chmod 600 app.conf
  ```

- **An output that is a symlink is written through**: the file it points to is
  replaced, the link stays, and evnx says `· wrote through current.conf -> shared/app.conf`.
- **`--output -` prints the rendered text on stdout** and writes no file. Everything
  else evnx prints then goes to stderr, so the text can be piped.
- **The template and the env file are never overwritten.** An `--output` that is
  the same file — by path, symlink or hard link — is refused:

  ```console
  $ evnx template --input in.tmpl --output .env
  Error: --output '.env' is the same file as the env file '.env'. Nothing was written; choose another --output.

  No verdict: evnx did not finish. This is not a clean result.
  ```

- **A missing directory is an error** that names `--mkdir` (see below).
- **Nothing is written when a run fails** — an unknown filter, a bad `|bool` or
  `|int` value, or `--strict` with an unresolved placeholder all stop the run before
  the file is touched.

## `--strict`

Without it, a placeholder with no value is **copied through literally** and the command
exits `0`:

```text
# in.tmpl
database_url = {{DATABASE_URL}}
```

```console
$ evnx template --input in.tmpl --output app.conf --no-gitignore

  Generate config from template

✓ Loaded 1 variables from .env
✓ Read template from in.tmpl
! Variable 'DATABASE_URL' referenced in template but not defined in .env
✓ Generated config at app.conf
· 1 placeholder was left unresolved and written through literally. Use --strict to make this an error.
  Docs: https://docs.evnx.dev/cli/commands/template

$ cat app.conf
database_url = {{DATABASE_URL}}
```

That file is no longer a template — it is a config file whose `database_url` is the
literal string `{{DATABASE_URL}}`, and whatever reads it next treats that as the
setting. `--strict` makes it an error:

```console
$ evnx template --input in.tmpl --output app.conf --strict --no-gitignore

  Generate config from template

✓ Loaded 1 variables from .env
✓ Read template from in.tmpl
! Variable 'DATABASE_URL' referenced in template but not defined in .env
Error: 1 variable referenced in in.tmpl has no value in .env: DATABASE_URL

Define it there, or give it a fallback with {{NAME|default:value}}.
Nothing was written to app.conf.

No verdict: evnx did not finish. This is not a clean result.
```

<Callout type="info">
The refusal happens **before** the output is written, so a failed run leaves no
half-built config behind for the next step in your pipeline to pick up.

A placeholder with a `|default:` is not undefined, so `--strict` accepts it:
`{{DATABASE_URL|default:sqlite://local.db}}` renders as `sqlite://local.db`. That is
how you keep a variable optional under a strict build.
</Callout>

## `--dry-run`

**v0.10.5+** — render the template and say what the real run would do, without
writing anything: whether the file would be created or replaced, through which
link, and which directory `--mkdir` would create.

```console
$ evnx template --input config.yaml.template --output config.yaml --dry-run

  Generate config from template

✓ Loaded 1 variables from .env
✓ Read template from config.yaml.template
! Variable 'REGION' referenced in template but not defined in .env
Dry run: nothing was written.
  would create config.yaml
  1 placeholder would be left unresolved
```

The report for an output that exists, for one that is a symlink, and for stdout:

```text
  would replace config.yaml
  would create shared/config.yaml through the link current.yaml
Dry run: nothing was printed.
  would print 2 lines, 1 placeholder unresolved to stdout
```

A dry run:

- **never prints a value** — not the rendered text, not even with `--output -`;
- **leaves `.gitignore` alone**, with or without `--gitignore`;
- **fails where the real run would**, with the same message and exit `2`: an unknown
  filter, a bad `|bool` or `|int` value, `--strict` with an unresolved placeholder, a
  missing directory without `--mkdir`, an `--output` that is the template or the env
  file.

That makes `--dry-run --strict` a check that a template renders against an env file,
without leaving a file full of secrets on the CI runner.

## `--mkdir`

**v0.10.5+** — an output whose directory does not exist is an error, and the error
says how to fix it:

```console
$ evnx template --input config.yaml.template --output deploy/k8s/config.yaml
...
Error: Failed to write generated config to: deploy/k8s/config.yaml: the directory deploy/k8s does not exist. Add --mkdir to create it.

No verdict: evnx did not finish. This is not a clean result.
```

With `--mkdir`, evnx creates the missing directories and names them:

```console
$ evnx template --input config.yaml.template --output deploy/k8s/config.yaml --mkdir --no-gitignore
...
Created directories deploy, deploy/k8s
✓ Generated config at deploy/k8s/config.yaml

$ stat -c '%a %n' deploy deploy/k8s deploy/k8s/config.yaml
700 deploy
700 deploy/k8s
600 deploy/k8s/config.yaml
```

Every directory `--mkdir` creates is readable by you only (`0700`). A directory that
already exists keeps its mode: with an existing `infra`, `--output infra/app/config.yaml
--mkdir` creates `infra/app` as `0700` and leaves `infra` alone. With `--dry-run`, the
report says `would create the directory deploy/k8s (--mkdir)` and nothing is created.

## Gitignore protection

Generated config files contain real values injected from `.env` and must never be
committed. After writing the output, `evnx template` checks whether git would pick it
up, and can add it to `.gitignore`.

**git decides, not the text of `.gitignore`** (**v0.10.3+**). evnx asks git whether the
output is ignored, so a `*.yml` or `config/` rule that already covers it counts, a
later `!out.yml` that re-includes it does not, and a file git already tracks is
recognised as such.

### Behaviour by flag and context

| Context | `--gitignore` | `--no-gitignore` | No flag |
|---------|--------------|-----------------|---------|
| **Interactive terminal** | Add it, no question | Skip, no warning | Ask: `'config.toml' may contain secrets — add it to .gitignore? [Y/n]`. Enter answers yes; `n` then Enter answers no |
| **CI / non-interactive** | Add it, no question | Skip, no warning | Warn only: `! 'config.toml' may contain secrets and is not in .gitignore`. Nothing is written |
| **Already ignored by git** | `✓ 'config.toml' is already ignored by git` | Skip silently | `✓ 'config.toml' is already ignored by git` |
| **Tracked by git** | Warn and suggest `git rm --cached`; no line added | Skip silently | Warn and suggest `git rm --cached`; no line added |
| **No git repository** | Warn `Not a git repository — cannot update .gitignore` | Skip silently | Skip silently |

The default is safe in both contexts: interactive users get a one-keystroke question,
CI pipelines get a visible warning without a blocking prompt.

### What gets written

Entries are grouped under a labelled section so they are easy to identify:

```gitignore
# ── evnx generated ─────────────────────────────────────────
# Written by evnx. These files may contain secrets — do not commit.
config.toml
k8s/configmap.yaml
```

The entry is always relative to the repository root, wherever you run the command
from, with any `..` resolved: `--output sub/../out.yml --gitignore` adds `out.yml`.
Running `evnx template` again with the same `--output` finds the file ignored and adds
nothing.

### A file git already tracks

A `.gitignore` line does not stop git from committing a file it already tracks, so
evnx does not add one. It says what does work:

```text
! 'tracked.conf' is tracked by git: a commit includes it whatever .gitignore says
     →  git rm --cached tracked.conf
```

### Git root detection

evnx walks ancestor directories from the current working directory looking for a `.git`
entry (directory or file, so worktrees are supported). The `.gitignore` it updates is
the one at that root.

<Callout type="danger">
  <strong>Output files outside the repository cannot be protected.</strong> <code>.gitignore</code> patterns cannot reach above the repository root, so for an <code>--output</code> such as <code>/srv/app/config.yaml</code> or <code>../config.yaml</code> evnx warns — <code>'/srv/app/config.yaml' is outside the git repository — .gitignore cannot protect it</code> — and leaves <code>.gitignore</code> alone, even with <code>--gitignore</code>.
</Callout>

## Variable substitution syntax

The template engine supports three styles for referencing variables from your `.env` file:

| Syntax | Example | Description |
|--------|---------|-------------|
| `{{VAR}}` | `{{DATABASE_URL}}` | Template style; the only one that takes a filter |
| `${VAR}` | `${DATABASE_URL}` | Shell style |
| `$VAR` | `$DATABASE_URL` | Bare; the name is the letters, digits and `_` that follow the `$` |

Spaces inside the braces are allowed (**v0.5.0+**), so these all render the same value:

```text
{{PORT}}  {{ PORT }}  ${PORT}  ${ PORT }  $PORT
{{APP_ENV|upper}}  {{ APP_ENV | upper }}
```

A `$` that is not followed by a name, as in `price=$5`, is left alone. A name that is
not in the env file — `$PATHNAME` in `https://example.com/$PATHNAME` — gets the same
warning as `{{PATHNAME}}` and is written through unchanged, or stops the run under
`--strict`.

## Filter transformations

Apply a transformation to a value with a pipe (`|`) inside double braces:

```text
{{VAR|filter}}
```

### Supported filters

| Filter | Result | Example |
|--------|--------|---------|
| `\|upper` | Uppercase | `production` → `PRODUCTION` |
| `\|lower` | Lowercase | `PRODUCTION` → `production` |
| `\|title` | **v0.10.5+** — Title Case: each word's first letter upper, the rest lower | `hello wORLD` → `Hello World` |
| `\|capitalize` | **v0.10.5+** — First character upper, the rest unchanged (what `\|title` did before 0.10.5) | `hello wORLD` → `Hello wORLD` |
| `\|bool` | **v0.10.5+** — `true` or `false` from a fixed list of words; anything else is an error | `on` → `true`, `n` → `false` |
| `\|int` | A whole number; anything else is an error | `8000` → `8000` |
| `\|json` | A quoted, escaped JSON string | `hello "world"` → `"hello \"world\""` |
| `\|default:VALUE` | `VALUE` when the variable is empty or not defined; its own value otherwise | `{{POOL\|default:10}}` → `10` |

`evnx template --help` prints the same list.

### One filter per placeholder

Chained filters are an **error** (**v0.10.5+**), and nothing is written:

```console
$ evnx template --input chain.tmpl --output app.yaml
...
Error: chain.tmpl has a filter evnx cannot apply:
  line 1: {{APP_ENV|upper|json}}: chained filters are not supported; use one filter per placeholder

Filters: upper, lower, title, capitalize, bool, int, json, default:VALUE.
Nothing was written to app.yaml.

No verdict: evnx did not finish. This is not a clean result.
```

A filter after a default is a chain too: `{{PORT|default:8080|int}}` and
`{{APP_ENV|default:x | upper}}` are reported the same way. A pipe followed by anything
that is not a filter name stays part of the default's text, so `{{SEP|default:a|b}}`
renders `a|b` when `SEP` is empty.

Before 0.10.5, `{{APP_ENV|upper|json}}` was copied into the output unchanged with exit
`0`, and `{{PORT|default:8080|int}}` rendered `8080|int`. Chaining is planned for
0.11.0. Until then, a value that needs both a fallback and `|int` or `|bool` gets its
fallback in `.env`.

### Unknown filters are errors

**v0.10.5+** — a filter evnx does not know stops the run. Every one is named with its
line, with a suggestion when a known filter is close:

```console
$ evnx template --input bad.tmpl --output app.yaml

  Generate config from template

✓ Loaded 2 variables from .env
✓ Read template from bad.tmpl
Error: bad.tmpl has 3 filters evnx cannot apply:
  line 1: {{PORT|innt}}: unknown filter `innt` — did you mean `int`?
  line 2: {{ APP_ENV | Upper }}: unknown filter `Upper` — did you mean `upper`?
  line 3: {{REGION|bogus}}: unknown filter `bogus`

Filters: upper, lower, title, capitalize, bool, int, json, default:VALUE.
Nothing was written to app.yaml.

No verdict: evnx did not finish. This is not a clean result.
```

Filter names are lowercase: `Upper` is not `upper`. The check applies to every
`{{NAME|filter}}` whose name is a variable name, whether or not the variable is
defined — `REGION` above is not. Before 0.10.5 all three were written into the output
unchanged, with exit `0`.

Placeholders of other template languages are not evnx references and pass through
untouched, so a Helm chart can be rendered in two stages:

```text
image: {{ .Values.image | quote }}    →    image: {{ .Values.image | quote }}
env: {{APP_ENV}}                      →    env: staging
```

### `|title` and `|capitalize`

`|title` follows Jinja: a word starts after whitespace or one of `-`, `(`, `[`, `{`,
`<`, and each word gets its first letter upper and the rest lower. `|capitalize`
changes the first character only.

| Value | `\|title` | `\|capitalize` |
|-------|-----------|----------------|
| `hello wORLD` | `Hello World` | `Hello wORLD` |
| `my API key` | `My Api Key` | `My API key` |
| `mary-jane o'neil` | `Mary-Jane O'neil` | `Mary-jane o'neil` |

<Callout type="info">
Before 0.10.5, `|title` changed only the first character. If a template relied on
that — an acronym such as `API` that must stay uppercase — switch it to `|capitalize`.
</Callout>

### `|bool`

| Value, in any case | Result |
|--------------------|--------|
| `true`, `yes`, `on`, `1`, `y` | `true` |
| `false`, `no`, `off`, `0`, `n` | `false` |
| anything else, including an empty value | error, nothing written |

```console
$ evnx template --input flags.tmpl --output flags.yaml
...
Error: Failed to process template substitutions: Variable 'FEATURE_BETA' value 'enabled' is not a boolean for |bool: use true/yes/on/1/y or false/no/off/0/n

No verdict: evnx did not finish. This is not a clean result.
```

Before 0.10.5 every value outside `true`, `yes` and `1` — `on`, `y`, `enabled`, a
typo, an empty value — became `false`, silently.

### Bad values are not printed when the name looks secret

A bad `|bool` or `|int` value is shown in the error, unless the variable's name looks
like a secret:

```text
Error: Failed to process template substitutions: Variable 'PORT' value '80a' is not a valid integer for |int filter: invalid digit found in string
Error: Failed to process template substitutions: Variable 'DB_PASSWORD' value '***' is not a boolean for |bool: use true/yes/on/1/y or false/no/off/0/n
```

### JSON filter example

The `|json` filter returns a quoted JSON string literal, with the surrounding double
quotes and any quotes inside escaped:

```text
# If DESCRIPTION = hello "world"
# Template:  "description": {{DESCRIPTION|json}}
# Output:    "description": "hello \"world\""
```

## Basic usage examples

### Generate a config file from template

```bash
evnx template --input config.yaml.template --output config.yaml
```

### Use a custom environment file

```bash
evnx template --input deploy.yaml.tpl --output deploy.yaml --env .env.production
```

`--env-name production` does the same:

```console
$ evnx template --input in.tmpl --output app.conf --env-name production --no-gitignore

  Generate config from template

✓ Loaded 1 variables from .env.production
✓ Read template from in.tmpl
✓ Generated config at app.conf
  Docs: https://docs.evnx.dev/cli/commands/template
```

The file is named `.env.production`, as `.env` is (**v0.10.5+**; it was
`./.env.production`).

### Print to stdout

```console
$ evnx template --input in.tmpl --output - 2>/dev/null
database_url = postgres://localhost/dev
```

Only the rendered text reaches stdout, so it can be piped to the next command.

### Check a template in CI without writing it

```bash
evnx template --input config.yaml.template --output config.yaml --env-name production --strict --dry-run
```

### Generate multiple configs in a script

```bash
#!/bin/bash
# One template, one config per environment — each output added to .gitignore
for env in dev staging prod; do
  evnx template \
    --input config.yaml.template \
    --output "config.${env}.yaml" \
    --env-name "$env" \
    --gitignore \
    --quiet
done
```

### Opt out of gitignore management

```bash
# You manage .gitignore externally (e.g. via a generator or monorepo tooling)
evnx template \
  --input config.yaml.template \
  --output config.yaml \
  --env .env.production \
  --no-gitignore
```

## When to use `evnx template`

| Scenario | Why use this command |
|----------|---------------------|
| **CI/CD pipeline config generation** | Generate environment-specific configs at build time without committing secrets |
| **Docker/Kubernetes deployments** | Create `docker-compose.yml` or `k8s/` manifests from templates using runtime env vars |
| **Multi-environment setups** | Maintain one template file, generate `config.dev.yaml`, `config.prod.yaml`, etc. |
| **Dynamic configuration injection** | Inject values from `.env` into config formats that don't natively support env vars (JSON, TOML) |
| **Safe secret handling** | Use `\|json` filter to properly escape values; avoid manual string concatenation bugs |

<Callout type="success">
  <strong>Pro tip:</strong> Store your template files with a <code>.template</code> or <code>.tpl</code> extension and commit them to version control. Generated output files contain real secrets — use <code>--gitignore</code> to let evnx add them to <code>.gitignore</code> automatically, or add them manually. Never commit generated output.
</Callout>

## Exit codes

| Code | Meaning | Use case |
|------|---------|----------|
| `0` | ✅ Written — or, with `--dry-run`, it would have been | Success in scripts/CI. Also returned when placeholders were left unresolved without `--strict` |
| `2` | 🚨 Nothing was written | A missing template or env file, a bad line in the env file, an unknown or chained filter, a bad `\|bool` or `\|int` value, an unresolved placeholder under `--strict`, a missing directory without `--mkdir`, an `--output` that is the template or the env file, I/O or permission errors |

`--dry-run` exits with the code the real run would.

## Troubleshooting

### "Failed to parse environment file" error

```text
Error: Failed to parse environment file: .env: .env does not exist
Error: Failed to parse environment file: .env.production: Invalid format at line 2: missing '=' separator
```

**Solution**: Create the file, point `--env` at the right one, or fix the line named.
Each line is `KEY=value` (spaces around `=` are accepted), `#` starts a comment, and a
value with spaces can be quoted: `KEY="value with spaces"`.

### "Variable 'X' referenced in template but not defined" warning

```text
! Variable 'MISSING_VAR' referenced in template but not defined in .env
· 1 placeholder was left unresolved and written through literally. Use --strict to make this an error.
```

**Solution**: Add the missing variable to your `.env` file, or give it a fallback:

```text
{{MISSING_VAR|default:fallback_value}}
```

In CI, add `--strict` so this fails the build instead of producing a config file with
`{{MISSING_VAR}}` in it.

### "filters evnx cannot apply" error

```text
Error: bad.tmpl has 3 filters evnx cannot apply:
  line 1: {{PORT|innt}}: unknown filter `innt` — did you mean `int`?
```

**Solution**: Correct the filter on the line named; the list of filters follows the
error. A chained filter (`{{X|upper|json}}`) is reported the same way: keep one.

### Filter value errors

```text
Error: Failed to process template substitutions: Variable 'PORT' value '80a' is not a valid integer for |int filter: invalid digit found in string
```

**Solution**: Fix the value in your `.env` file. `|default:` covers a variable that is
missing or empty, not one that holds a bad value, and it cannot be combined with
`|int` or `|bool` on the same placeholder. For `|bool`, the accepted words are listed
in the error.

### "the directory … does not exist" error

```text
Error: Failed to write generated config to: deploy/k8s/config.yaml: the directory deploy/k8s does not exist. Add --mkdir to create it.
```

**Solution**: Add `--mkdir`, or create the directory yourself.

### "Not a git repository" warning with `--gitignore`

```text
! Not a git repository — cannot update .gitignore
```

**Cause**: evnx walks ancestor directories looking for `.git` and reached the
filesystem root without finding one. This happens when running outside a git repository
or from a temp directory in CI.

**Solutions**:
- Run the command from within your repository
- If you are not using git, drop `--gitignore` (without it the check is silent outside a repository), or add `--no-gitignore`
- If using git worktrees, the `.git` file (not directory) is also detected correctly

### Output file already ignored

```text
✓ 'config.toml' is already ignored by git
```

**This is correct behavior** — git already ignores the file, by an entry evnx wrote or
by a rule of your own such as `*.toml`, so nothing is added. Running `evnx template`
repeatedly never produces duplicate entries.

### JSON filter output has unexpected quotes

```text
# Template: key={{VALUE|json}}
# Output:   key="hello \"world\""
```

**This is correct behavior.** The `|json` filter returns a properly quoted JSON string literal, including the surrounding double quotes. Use it when embedding values directly inside JSON structures:

```json
{
  "description": {{DESCRIPTION|json}}
}
```

If `DESCRIPTION = hello "world"`, the output will be:

```json
{
  "description": "hello \"world\""
}
```

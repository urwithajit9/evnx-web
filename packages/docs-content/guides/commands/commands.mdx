```bash
evnx commands
```

Lists every command **this** binary has, grouped, with the optional features it was compiled with.

<Callout type="warning">
**"This binary" is the whole point.** `cloud`, `migrate` and `backup` are optional Cargo features, so two installs reporting the same version can have very different command sets — and `--version` cannot tell you which one you have.
</Callout>

## What it prints

```text
  evnx 0.10.7
  built with: net, migrate, backup, cloud

  On this machine
    init         Interactive project setup — generates .env.example
    add          Add environment variables to existing .env files
    validate     Check .env against .env.example, find issues
    scan         Detect secrets that look real (AWS keys, tokens, etc.)
    diff         Compare .env vs .env.example — show missing/extra vars
    convert      Transform `.env` files into multiple output formats
    migrate      Full migration workflow to secret managers
    sync         Keep .env and .env.example in sync
    template     Generate config files from templates
    backup       Create encrypted backup of .env
    restore      Restore from encrypted backup
    doctor       Check .env files, Git config, project structure, and security
    spec         Declare what each variable is: required, format, secret
    commands     Every command this build has, and which features it was compiled with
    completions  Generate shell completions
    update       Show how to upgrade, and optionally whether a newer release exists

  With an evnx account
    auth         Manage your evnx cloud account
    org          Manage organisations — billing and a directory
    vault        Manage encrypted vaults
    cloud        Sync encrypted .env files with evnx cloud

  20 commands (83 with sub-commands). `evnx <command> --help` for any of them.
  `evnx commands --json` emits the whole tree, for tooling.

  Guides: https://docs.evnx.dev/cli
```

The closing line counts the commands listed above it and, in brackets, every
command including sub-commands such as `vault share` (**v0.10.7+**; it used to say
`83 commands` under a list of 20).

`-q` has no effect: the list is the answer.

## When a command is "missing"

If `evnx vault` reports *unrecognized subcommand*, one of two things is true, and this command tells you which.

### Your build has no cloud feature

```text
  evnx 0.10.7
  built with no optional features
  ...
  ! This build has NO cloud commands — no auth, vault, cloud or org.
    It was compiled without the `cloud` feature.

    Install from a channel that includes them (`evnx update` lists
    every channel), or build with:
      cargo install evnx --all-features

  13 commands (18 with sub-commands). `evnx <command> --help` for any of them.
```

<Callout type="info">
Every prebuilt binary carries the cloud commands — npm, PyPI, Homebrew, Scoop, winget and the GitHub Release are all built with `--all-features`.

⚠️ **PyPI did not, up to and including 0.9.0.** `pip install evnx` and `pipx install evnx` gave a binary with no `auth`, `vault`, `cloud` or `org` at all, from 0.4.0 onward. Fixed from 0.10.0.

`cargo install evnx` is the other exception, and it is deliberate — it compiles from source with no features. Use `cargo install evnx --all-features`.
</Callout>

### A different evnx is answering

The commands are there; you are running a different binary.

```bash
which -a evnx
```

If more than one path appears, the first one wins. A package-manager install often sits ahead of `~/.cargo/bin`, so `cargo install` appears to succeed while the old binary keeps answering.

`evnx commands` run through an explicit path tells you what that specific binary has:

```bash
~/.cargo/bin/evnx commands
```

## For tooling

```bash
evnx commands --json
evnx commands --json --compact
```

The whole command tree: `schema`, `evnx_version`, `features`, and `commands` — one
entry per command and sub-command with its `path`, `name`, `about`, `aliases`,
`visible_aliases`, `hidden` flag, `args`, and the `docs_url` of its guide. Every
top-level command has a `docs_url` (**v0.10.7+**; `completions` and `update` had
none).

A release check that the build carries the cloud commands — it exits `1` for a build
without them:

```bash
evnx commands --json | jq -e '.features | index("cloud")'
```

<Callout type="info">
⚠️ It is generated by walking the CLI's own argument parser, so it cannot disagree with the binary. That is what it is for — `app.evnx.dev/tour` and the documentation checks are built from it rather than from a hand-written list, because five documentation errors in this project came from exactly such a list drifting.

The payload carries a `schema` number (currently `1`). Check it: the shape may change, and that is not a breaking change to the command.
</Callout>

<Callout type="warning">
**Do not parse the plain output.** It is for people, it carries no compatibility promise, and `--json` exists so you never have to.
</Callout>

ⓘ `evnx surface` is an alias, kept because tooling already calls it that.

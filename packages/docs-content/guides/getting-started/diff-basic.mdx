## What is diff and why use it?

`.env.example` is the team's list of the variables a project needs. Your `.env` is your
copy with real values. They drift: someone adds `REDIS_URL` to the template, and your app
fails at startup on a key you never had.

`evnx diff` compares the two **by key name**. It does not compare values against the
template, because a real value differs from its placeholder by design. To compare values,
compare two real environments (step 4).

<Callout type="danger" title="Values are hidden by default">
No value is printed unless you pass `--show-values`, and even then secrets are masked.
Safe to run in a shared terminal or a CI log.
</Callout>

## 1. Your first diff

A teammate added `REDIS_URL` to the template. Your `.env` also has a key of your own:

```bash
cat .env.example
```

```text
DATABASE_URL=postgres://user:password@localhost:5432/app
REDIS_URL=redis://localhost:6379
STRIPE_SECRET_KEY=sk_test_YOUR_KEY
PORT=3000
NODE_ENV=development
```

```bash
evnx diff
```

```text
  evnx diff  .env ↔ .env.example

Missing from .env (present in .env.example):
  + REDIS_URL

Extra in .env (not in .env.example):
  - LOCAL_DEBUG_MODE

  1 missing from .env  ·  1 not in .env.example
  values not compared against a template (--values to compare them)
```

- `+` is a key your `.env` **lacks**. Add it.
- `-` is a key only your `.env` has. Fine if it is yours alone; otherwise add it to the
  template (`evnx sync` does that).

It exits `1`, because both count by default.

## 2. Fix the missing key

```bash
echo 'REDIS_URL=redis://localhost:6379' >> .env
evnx diff
```

```text
  evnx diff  .env ↔ .env.example

Extra in .env (not in .env.example):
  - LOCAL_DEBUG_MODE

  1 not in .env.example
  values not compared against a template (--values to compare them)
```

Still exit `1`: the extra key counts too. When both files have exactly the same keys you
get:

```text
✓ .env and .env.example have the same keys
```

and exit `0`.

## 3. Decide what fails

Usually the question is only "does my `.env` have everything the template declares?".
`--fail-on missing` asks exactly that:

```bash
evnx diff --fail-on missing
echo $?
```

The report is the same as in step 2 — `diff` always lists everything — but the exit code
is `0`, because nothing is missing. The other choices are `extra` and `different`, comma
separated.

To leave a local key out of the comparison altogether:

```bash
evnx diff --ignore-keys LOCAL_DEBUG_MODE
```

```text
✓ .env and .env.example have the same keys (1 key ignored)
```

## 4. Compare two environments

This is the diff that compares values. With `.env.production` and `.env.staging`:

```bash
evnx diff --env-name production --against staging
```

```text
  evnx diff  .env.production ↔ .env.staging

Extra in .env.production (not in .env.staging):
  - SENTRY_DSN

Different values:
  ~ DATABASE_URL
  ~ STRIPE_SECRET_KEY
  ~ NODE_ENV

  1 not in .env.staging  ·  3 different values
```

`~` is a key whose values differ. Add `--show-values` to see them. Secrets stay masked, by
name and by value:

```text
Different values:
  ~ DATABASE_URL
    .env.staging: postgres://admin:***@db.stg:5432/app
    .env.production: postgres://admin:***@db.prod:5432/app
  ~ STRIPE_SECRET_KEY
    .env.staging: ***
    .env.production: ***
  ~ NODE_ENV
    .env.staging: staging
    .env.production: production
```

A key is masked when its name contains `PASSWORD`, `SECRET`, `TOKEN`, `API_KEY`, `AUTH`
and similar, or ends with `_KEY`, `_SECRET` or `_TOKEN` — so `MY_CUSTOM_SECRET_VALUE` is
masked too. A password inside a URL is masked whatever the key is called.

## 5. Use it in CI

The exit code is the gate:

```bash
evnx diff --fail-on missing
```

For a script, JSON has a `summary`. On the files from step 1:

```bash
evnx diff --format json | jq '.summary'
```

```json
{
  "missing": 1,
  "extra": 1,
  "different": 0,
  "total": 2
}
```

Exit codes: `0` nothing `--fail-on` counts, `1` differences, `2` could not run — a
missing file, a bad flag, or `.env does not exist`.

## 6. As a pre-commit hook

```yaml
# .pre-commit-config.yaml
repos:
  - repo: https://github.com/urwithajit9/evnx
    rev: v0.10.18
    hooks:
      - id: evnx-diff
```

The shipped hook runs `evnx diff --fail-on missing --skip-without-env`: it blocks a commit
when `.env` lacks a template key, ignores extra local keys, and skips a fresh clone that
has no `.env` yet.

## Other formats

`--format patch` lists the lines to add and remove, with values withheld:

```text
# Add these to .env:
+ REDIS_URL=<withheld>

# Remove these from .env:
- LOCAL_DEBUG_MODE=<withheld>
```

It is a list for a human, **not** input for `patch(1)`. `--interactive` (`-i`) asks about
each line, with `--format patch` only, and writes nothing.

## Troubleshooting

**`Error: .env does not exist`** — you are in a fresh clone. Create it from the template
with `evnx sync --direction reverse`, then fill in the values.

**Every value shows as different** — you passed `--values` against the template. Values
differ from placeholders by design; drop the flag.

**`--with-stats` or `--interactive` is refused** — `--with-stats` needs `--format json`,
and `--interactive` needs `--format patch`. Both exit 2 otherwise.

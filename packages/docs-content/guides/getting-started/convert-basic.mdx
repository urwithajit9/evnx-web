# Convert basics

This guide walks through the common `evnx convert` workflows with the output each one
prints. For every flag, see [evnx convert](/guides/commands/convert).

  <Prerequisite href="/guides/getting-started/installation">Install evnx</Prerequisite>

## Your starting .env

Every example on this page uses this `.env`:

```env
# .env
DATABASE_URL=postgres://user:pass@localhost:5432/mydb
REDIS_URL=redis://localhost:6379
AWS_ACCESS_KEY_ID=AKIAIOSFODNN7EXAMPLE
AWS_SECRET_ACCESS_KEY=wJalrXUtnFEMI/K7MDENG/bPxRfiCYEXAMPLEKEY
AWS_REGION=us-east-1
APP_DEBUG=false
APP_PORT=3000
APP_LOG_LEVEL=info
TEST_ONLY_VAR=not-for-prod
```

The converted output goes to stdout; evnx's own lines (the `Docs:` link, notices) go
to stderr, so `>` and `|` carry the output alone.

## Interactive mode

Run `evnx convert` with no flags to pick a format from a menu:

```bash
evnx convert
```

```text
Select output format:
> json - Generic JSON key-value object
  yaml - Generic YAML key-value format
  shell - Shell export script (bash/zsh)
  aws-secrets - AWS Secrets Manager JSON (for create-secret --secret-string)
  gcp-secrets - GCP Secret Manager script (gcloud; needs --project)
  ...
```

Use ↑/↓ and Enter. The menu needs a terminal: in a script, pass `--to`.

## Basic format conversion

### JSON

```bash
evnx convert --to json
```

```json
{
  "DATABASE_URL": "postgres://user:pass@localhost:5432/mydb",
  "REDIS_URL": "redis://localhost:6379",
  "AWS_ACCESS_KEY_ID": "AKIAIOSFODNN7EXAMPLE",
  "AWS_SECRET_ACCESS_KEY": "wJalrXUtnFEMI/K7MDENG/bPxRfiCYEXAMPLEKEY",
  "AWS_REGION": "us-east-1",
  "APP_DEBUG": "false",
  "APP_PORT": "3000",
  "APP_LOG_LEVEL": "info",
  "TEST_ONLY_VAR": "not-for-prod"
}
```

### YAML

```bash
evnx convert --to yaml
```

```yaml
DATABASE_URL: postgres://user:pass@localhost:5432/mydb
REDIS_URL: redis://localhost:6379
AWS_ACCESS_KEY_ID: AKIAIOSFODNN7EXAMPLE
AWS_SECRET_ACCESS_KEY: wJalrXUtnFEMI/K7MDENG/bPxRfiCYEXAMPLEKEY
AWS_REGION: us-east-1
APP_DEBUG: 'false'
APP_PORT: '3000'
APP_LOG_LEVEL: info
TEST_ONLY_VAR: not-for-prod
```

Values that YAML would read as a number or a boolean are quoted, so they stay strings.

### Shell export script

```bash
evnx convert --to shell
```

```bash
#!/bin/bash
# Generated by evnx

export DATABASE_URL='postgres://user:pass@localhost:5432/mydb'
export REDIS_URL='redis://localhost:6379'
export AWS_ACCESS_KEY_ID='AKIAIOSFODNN7EXAMPLE'
export AWS_SECRET_ACCESS_KEY='wJalrXUtnFEMI/K7MDENG/bPxRfiCYEXAMPLEKEY'
export AWS_REGION='us-east-1'
export APP_DEBUG='false'
export APP_PORT='3000'
export APP_LOG_LEVEL='info'
export TEST_ONLY_VAR='not-for-prod'
```

Single quotes, so a `$`, a backtick or `$(…)` in a value is written as it is and never
runs when you `source` the script.

## Writing to a file

Use `--output` (or `-o`) instead of `>`:

```bash
evnx convert --to json --output config.json
evnx convert --to yaml -o config.yaml
evnx convert --to terraform --output prod.tfvars
```

```text
✓ Converted successfully
Output written to: config.json
```

The file holds every value from your `.env`, so it is created readable by you only
(`0600`). If it already exists, evnx stops and changes nothing; add `--force` to replace
it. In a git repository evnx also checks `.gitignore` for the file and warns when it is
not covered — `--gitignore` adds it for you.

## Filtering variables

### Include only matching names

```bash
evnx convert --to json --include "AWS_*"
```

```json
{
  "AWS_ACCESS_KEY_ID": "AKIAIOSFODNN7EXAMPLE",
  "AWS_SECRET_ACCESS_KEY": "wJalrXUtnFEMI/K7MDENG/bPxRfiCYEXAMPLEKEY",
  "AWS_REGION": "us-east-1"
}
```

Several patterns, comma-separated (or repeat `--include`):

```bash
evnx convert --to json --include "AWS_*,REDIS_URL"
```

```json
{
  "REDIS_URL": "redis://localhost:6379",
  "AWS_ACCESS_KEY_ID": "AKIAIOSFODNN7EXAMPLE",
  "AWS_SECRET_ACCESS_KEY": "wJalrXUtnFEMI/K7MDENG/bPxRfiCYEXAMPLEKEY",
  "AWS_REGION": "us-east-1"
}
```

Names keep the order they have in `.env`. `?` matches one character
(`--include "APP_?ORT"` keeps `APP_PORT`), a `*` can sit anywhere, and matching is
case-sensitive.

### Exclude matching names

```bash
evnx convert --to json --exclude "TEST_*"
```

Every variable except `TEST_ONLY_VAR`.

### Combine include and exclude

Exclude wins, so you can carve a name out of a broad match:

```bash
evnx convert --to json --include "APP_*" --exclude "*_DEBUG"
```

```json
{
  "APP_PORT": "3000",
  "APP_LOG_LEVEL": "info"
}
```

### When nothing matches

A pattern that matches nothing is usually a typo, so evnx stops instead of printing `{}`:

```bash
evnx convert --to json --include "NOPE_*"
```

```text
Error: --include/--exclude left nothing to convert — all 9 variable(s) were filtered out.
  Check the patterns: they are case-sensitive globs matched against variable names.
  Pass --allow-empty to write the empty output anyway.
```

It exits `2`. Add `--allow-empty` when an empty result is what you want.

## Renaming keys

### lowercase

```bash
evnx convert --to json --include "APP_*" --transform lowercase
```

```json
{
  "app_debug": "false",
  "app_port": "3000",
  "app_log_level": "info"
}
```

### camelCase

Useful for JavaScript and TypeScript configuration:

```bash
evnx convert --to json --include "APP_*" --transform camelCase
```

```json
{
  "appDebug": "false",
  "appPort": "3000",
  "appLogLevel": "info"
}
```

`snake_case` gives `app_debug` for these names, and `uppercase` leaves them as they are.

### A prefix

`--prefix` is added to every name before `--transform`:

```bash
evnx convert --to json --include "DATABASE_URL" --prefix "MYAPP_"
```

```json
{
  "MYAPP_DATABASE_URL": "postgres://user:pass@localhost:5432/mydb"
}
```

Combined, `APP_PORT` → `prod_APP_PORT` → `prodAppPort`:

```bash
evnx convert --to json --include "APP_*" --prefix "prod_" --transform camelCase
```

```json
{
  "prodAppDebug": "false",
  "prodAppPort": "3000",
  "prodAppLogLevel": "info"
}
```

If two names would become the same name, evnx stops and names both; see
[Names that collide](/guides/commands/convert#names-that-collide).

## Kubernetes Secret

A Secret needs a name, so `--name` is required:

```bash
evnx convert --to kubernetes --name myapp-env \
  --include "DATABASE_URL" \
  --output k8s-secret.yaml
```

`k8s-secret.yaml`:

```yaml
apiVersion: v1
kind: Secret
metadata:
  name: myapp-env
type: Opaque
stringData:
  DATABASE_URL: "postgres://user:pass@localhost:5432/mydb"
```

Values are written as they are under `stringData:`; Kubernetes encodes them when you
apply the file. Add `--namespace prod` to place it, and `--base64` if you want `data:`
with the values already encoded:

```yaml
data:
  DATABASE_URL: "cG9zdGdyZXM6Ly91c2VyOnBhc3NAbG9jYWxob3N0OjU0MzIvbXlkYg=="
```

```bash
kubectl apply -f k8s-secret.yaml
```

## Base64-encoding values

`--base64` encodes every value, in any format:

```bash
evnx convert --to json --include "AWS_*" --base64
```

```json
{
  "AWS_ACCESS_KEY_ID": "QUtJQUlPU0ZPRE5ON0VYQU1QTEU=",
  "AWS_SECRET_ACCESS_KEY": "d0phbHJYVXRuRkVNSS9LN01ERU5HL2JQeFJmaUNZRVhBTVBMRUtFWQ==",
  "AWS_REGION": "dXMtZWFzdC0x"
}
```

## Handing off to a cloud CLI

evnx writes the commands or payload; the provider's CLI does the upload, with your
credentials.

### AWS Secrets Manager

```bash
evnx convert --to aws-secrets | \
  aws secretsmanager create-secret \
    --name prod/myapp \
    --secret-string file:///dev/stdin
```

`file:///dev/stdin` works on Linux and macOS, not on Windows.

### Google Cloud Secret Manager

```bash
evnx convert --to gcp-secrets --project my-gcp-project --output upload.sh
bash upload.sh
```

The script creates each secret, or adds a new version when it already exists, so you
can run it again after changing a value. Names are lowercased with `-` for `_`
(`DATABASE_URL` → `database-url`).

### Heroku

```bash
evnx convert --to heroku --heroku-app my-app --exclude "TEST_*" | bash
```

The script runs one `heroku config:set` per variable:

```bash
heroku config:set DATABASE_URL="postgres://user:pass@localhost:5432/mydb" --app my-app || echo "Failed to set DATABASE_URL"
heroku config:set REDIS_URL="redis://localhost:6379" --app my-app || echo "Failed to set REDIS_URL"
```

Heroku restarts the app on each config change, so for many variables `evnx migrate --to
heroku` (one call) restarts it once.

## GitHub Actions

`--to github-actions` prints the names and values to paste into **Settings → Secrets and
variables → Actions**:

```bash
evnx convert --to github-actions --include "APP_*"
```

```text
Paste these into Settings → Secrets and variables → Actions:

Name: APP_DEBUG
Value: false
---
Name: APP_PORT
Value: 3000
---
Name: APP_LOG_LEVEL
Value: info

(3 secrets total — paste each one individually)
```

It is text for a person, not a script. To set secrets from the command line,
`gh secret set -f <file>` reads a dotenv file, and
[`evnx migrate --to github-actions`](/guides/commands/migrate) uploads through the API.

## Terraform

```bash
evnx convert --to terraform --exclude "TEST_*" --output prod.tfvars
```

`prod.tfvars`:

```hcl
# Generated by evnx

database_url = "postgres://user:pass@localhost:5432/mydb"
redis_url = "redis://localhost:6379"
aws_access_key_id = "AKIAIOSFODNN7EXAMPLE"
aws_secret_access_key = "wJalrXUtnFEMI/K7MDENG/bPxRfiCYEXAMPLEKEY"
aws_region = "us-east-1"
app_debug = "false"
app_port = "3000"
app_log_level = "info"
```

Names are lowercased for Terraform. Your module declares a `variable` for each name it
uses; Terraform warns about values for variables it does not declare.

## Verbose output

`--verbose` (or `-v`) reports progress on stderr, leaving stdout for the output:

```bash
evnx convert --to json --include APP_PORT --verbose 2>convert.log
```

`convert.log`:

```text
· Running convert in verbose mode: .env
· Loaded 9 variables from .env
· Converting to json format…
✓ Output written to stdout
  Docs: https://docs.evnx.dev/cli/commands/convert
```

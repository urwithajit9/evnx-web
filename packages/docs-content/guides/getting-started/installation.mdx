evnx is a single static binary with no runtime dependencies. Pick your platform and you'll be running in under two minutes.

## Prerequisites

- **macOS / Linux**: curl, bash
- **Windows**: winget (Windows Package Manager) or Rust toolchain
- **Cargo (all platforms)**: Rust toolchain via [rustup.rs](https://rustup.rs)

---

## macOS & Linux

The fastest way is the install script:

```bash
curl -fsSL https://dotenv.space/install.sh | bash
```

The script:
1. Detects your OS and architecture (x86_64 / arm64)
2. Downloads the correct binary from GitHub Releases
3. Verifies the checksum, and refuses to install if it is missing or wrong
4. **v0.11.0+** — with a signed-in GitHub CLI (`gh` 2.49+), verifies the archive's build
   provenance: one not built by evnx's release workflow from that tag is refused. Without
   `gh`, it says the check was skipped
5. Installs to `/usr/local/bin` if you can write there, otherwise to `~/.local/bin`
   if that folder exists. It does **not** edit your `PATH`; if `~/.local/bin` is not
   on it, add `export PATH="$HOME/.local/bin:$PATH"` to your shell profile

Pin a version, or choose the folder:

```bash
curl -fsSL https://dotenv.space/install.sh | EVNX_VERSION=0.11.0 bash
curl -fsSL https://dotenv.space/install.sh | EVNX_INSTALL_DIR="$HOME/bin" bash
```

Verify the installation:

```bash
evnx --version
```

### Homebrew

```bash
brew install urwithajit9/evnx/evnx
```

### npm

```bash
npm install -g @evnx/cli
```

Without a global install (**v0.10.6+**; up to 0.10.5 only `-g` gave an `evnx`
command, and these two forms reported `evnx: not found`):

```bash
npx @evnx/cli --version              # run once, nothing installed
npm install --save-dev @evnx/cli     # per project; then `npx evnx …` or an npm script
```

### pipx

```bash
pipx install evnx
```

## Docker

No install step at all — useful in CI, or to try evnx without putting it on your
machine:

```bash
docker run --rm -v "$PWD:/work" ghcr.io/urwithajit9/evnx scan
```

The image is built from the same static binary as the release tarballs, so it is
the same program. It is multi-arch (`amd64` and `arm64`) and about 27 MB.

<Callout type="warning">
**Commands that write files need your own user id**, or the container creates
files your host account cannot edit:

```bash
docker run --rm --user "$(id -u):$(id -g)" -v "$PWD:/work" \
  ghcr.io/urwithajit9/evnx sync --direction forward
```

Read-only commands — `scan`, `validate`, `diff`, `convert` to stdout — need
nothing extra. This is not an evnx quirk: it applies to every container that
writes into a mounted directory.
</Callout>

Pin a version rather than tracking `latest` in a pipeline:

```bash
docker run --rm -v "$PWD:/work" ghcr.io/urwithajit9/evnx:0.11.0 scan
```

In GitHub Actions the container form usually reads better than an install step:

```yaml
- name: Scan for secrets
  run: |
    docker run --rm -v "$PWD:/work" ghcr.io/urwithajit9/evnx:0.11.0 \
      scan --severity high
```

⚠️ `evnx cloud` works in the container, but the master password still has to
reach it — pass it on stdin with `--password-stdin`, never as an argument or a
plain `-e` variable.

## Cargo (All Platforms)

Install the stable release from [crates.io](https://crates.io/crates/evnx):

```bash
cargo install evnx --all-features
```

<Callout type="danger">
**Use `--all-features`, not `--features full`.**

`full` is `migrate` + `backup`. It does **not** include `cloud`, so
`cargo install evnx --features full` gives you a binary with no `auth`, `vault`
or `cloud` commands — verified by building it.

This page previously described `--features full` as "all optional features
(cloud sync, extra format targets)". That was wrong, and it would have left you
unable to use the feature you installed it for.
</Callout>

Plain `cargo install evnx` builds with `default = []` — the local commands only,
no cloud. That is the right choice if you do not want the network stack.

<Callout type="info" title="Compile times">
Cargo builds from source, so the first install takes 60–90 seconds. Subsequent installs are faster because Cargo caches dependencies.
</Callout>

<Callout type="tip">
**Every other channel already includes the cloud commands.** The prebuilt
binaries — the install script, Homebrew, npm, pipx, Scoop, winget, Docker and the
GitHub Release — are built with `--all-features`. `cargo install` is the only one
that needs the flag, because it is the only one that compiles from source.
</Callout>

## Verify your download

**v0.11.0+** — every release archive has a `.sha256` beside it and a signed **build
provenance** attestation. The checksum proves the file is intact; the attestation proves
it was built by evnx's release workflow, from the tagged commit, on a GitHub-hosted
runner.

```bash
curl -fsSLO https://github.com/urwithajit9/evnx/releases/download/v0.11.0/evnx-x86_64-unknown-linux-musl.tar.gz
curl -fsSLO https://github.com/urwithajit9/evnx/releases/download/v0.11.0/evnx-x86_64-unknown-linux-musl.tar.gz.sha256
sha256sum -c evnx-x86_64-unknown-linux-musl.tar.gz.sha256        # macOS: shasum -a 256 -c
gh attestation verify evnx-x86_64-unknown-linux-musl.tar.gz -R urwithajit9/evnx \
  --signer-workflow urwithajit9/evnx/.github/workflows/release.yml \
  --source-ref refs/tags/v0.11.0 --deny-self-hosted-runners
tar -xzf evnx-x86_64-unknown-linux-musl.tar.gz
install -m 755 evnx-x86_64-unknown-linux-musl ~/.local/bin/evnx
```

The archive holds one file named after its target (`evnx-x86_64-unknown-linux-musl`;
on Windows a `.zip` with `evnx-x86_64-pc-windows-msvc.exe`). `gh attestation verify`
needs `gh auth login`. A tampered file, another repository or another tag fails it.
Releases before v0.11.0 carry no attestation; the install script checks both for you.

## Run Your First Check

Before setting anything up, try this in any project directory:

```bash
cd your-project
evnx doctor
```

`doctor` runs five checks on the folder you are in and prints one line for each:

- `.env` exists, is in `.gitignore`, and parses
- `.env.example` exists and is tracked by git
- the project type (Node, Python, Rust and others) and its dependencies
- Docker configuration files
- file permissions on `.env` (`600` recommended)

It exits `1` when a check fails. `evnx doctor --fix` repairs what it can: it adds the
`.env*` lines to `.gitignore` and tightens the file's permissions. The
[Quick Start](/guides/getting-started/quick-start) shows a real run. To look for
secrets, run `evnx scan`.

## Install the Pre-commit Hook (Recommended)

This is the most important step. The pre-commit hook runs `evnx scan` automatically before every `git commit`, blocking commits that contain secrets.

### Using pre-commit

Add to your `.pre-commit-config.yaml`:

```yaml
repos:
  - repo: local
    hooks:
      - id: evnx-scan
        name: evnx secret scan
        entry: evnx scan
        language: system
        files: '\.env'
        pass_filenames: false
```

<Callout type="warning">
Both hooks above used to pass `--exit-code`. **That flag does not exist** — the command
failed with an argument error, so the hook blocked **every** commit, clean or not, while
printing "secrets detected". `evnx scan` already exits non-zero when it reports something,
which is all a hook needs.
</Callout>

Then install:

```bash
pre-commit install
```

### Manual git hook

```bash
# Create the hook file
cat > .git/hooks/pre-commit << 'EOF'
#!/bin/bash
evnx scan
status=$?
if [ "$status" -eq 1 ]; then
  echo "evnx: secrets detected. Commit blocked."
  exit 1
elif [ "$status" -ne 0 ]; then
  echo "evnx: the scan could not run (exit $status). Commit blocked."
  exit "$status"
fi
EOF

chmod +x .git/hooks/pre-commit
```

<Callout type="warning" title="Team setup">
The `.pre-commit-config.yaml` approach is better for teams — it's committed to the repo, so every developer gets the hook automatically when they run `pre-commit install`.
</Callout>

## Updating evnx

```bash
# Prints the upgrade command for the way you installed it (0.7.0+)
evnx update

# If installed via install script
curl -fsSL https://dotenv.space/install.sh | bash

# If installed via cargo: --all-features, or the cloud commands are dropped
cargo install evnx --all-features --force

# Check which version you are on
evnx --version
```

Upgrade through the channel you installed with. Installing through a second
channel adds a second copy instead of replacing the first, and the older one can
keep winning on your `PATH`. [Managing your evnx install](/guides/reference/managing-your-evnx-install)
has every channel's upgrade and uninstall command, and fixes for the common problems.

<Callout type="warning">
Corrected September 2026: this block ended with `evnx doctor --check-updates`, which does
not exist — `doctor` diagnoses a project and never reaches the network. Compare
`evnx --version` against the [latest release](https://github.com/urwithajit9/evnx/releases).
</Callout>

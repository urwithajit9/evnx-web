Every time you start a new project, you explain the same things to your AI agent: how to run `evnx scan`, what flags `evnx convert` takes, which CI/CD snippet to use. Today that stops.

evnx now ships with two **agent skills** — packaged knowledge that installs into your AI coding agent once and stays there. No re-explaining. No pasting docs. Your agent knows evnx the way you do.

## The problem

AI coding agents are useful for environment setup, CI/CD scaffolding, and secrets management workflows — but they have no default knowledge of evnx. Every new project means re-explaining the same commands, correcting wrong flags, and fixing generated pipelines that reference tools you don't use.

The [Agent Skills standard](https://skills.sh) solves this. Skills are versioned knowledge packages that install into your agent once and activate automatically when the task matches. Not a plugin, not an MCP server — just expertise your agent has permanently.

## The two evnx skills

**`dotenv-best-practices`** teaches your agent the fundamentals that apply to any project, regardless of whether evnx is installed. The `.env` file hierarchy, the boolean string trap, how `NEXT_PUBLIC_` and `VITE_` prefixes actually work, what a valid `.env.example` looks like, and the security checklist before every deploy.

**`evnx-cli`** teaches your agent the complete evnx toolchain. Every command, every flag, all 14 conversion formats, CI/CD integration recipes, and — critically — the known limitations so your agent doesn't suggest syntax that doesn't work.

## Step 1 — Install evnx

The skills teach your agent to use evnx. Make sure evnx is installed first.

<CodeTabs>

<Tab label="macOS / Linux">

</Tab>

<Tab label="Cargo">


```bash

```

</TerminalOutput>

A `skills-lock.json` file is created in your project directory. Commit it alongside a `.gitignore` update for the agent config folders — these are developer-local and should not be shared:

```bash
cat >> .gitignore << 'EOF'

# Agent config — local per developer, not committed
.agents/
.claude/
.cursor/
.cline/
.windsurf/
.roo/
.goose/
EOF

git add .gitignore skills-lock.json
git commit -m "chore: add evnx agent skills"
```

Teammates who clone the repo run `npx skills add urwithajit9/agent-skills` and get the same pinned skill versions.

## What changes in practice

Before the `evnx-cli` skill, asking your agent to set up secret scanning in a GitHub Actions pipeline produces a generic `detect-secrets` snippet or a placeholder. After the skill is installed, the same prompt produces:

```yaml
- name: Install evnx
  run: curl -fsSL https://dotenv.space/install.sh | bash

- name: Scan for secrets
  run: evnx scan --format sarif > scan-results.sarif

- name: Upload to GitHub Security tab
  uses: github/codeql-action/upload-sarif@v2
  if: always()
  with:
    sarif_file: scan-results.sarif
```

Correct flags. Correct SARIF integration. No edits needed.

The `dotenv-best-practices` skill changes how your agent handles `.env` setup questions. Instead of generic advice, it applies the file hierarchy, the gitignore pattern, the startup validation pattern for your specific stack, and the boolean parsing fix for Python and TypeScript — without being prompted.

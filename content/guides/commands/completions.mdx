`evnx completions <SHELL>` prints a completion script to **stdout**. It writes
nothing else there, so you can redirect it straight into a file.

<Prerequisites>
  <Prerequisite href="/guides/getting-started/installation">Install evnx</Prerequisite>
</Prerequisites>

---

## Commands

<CommandSignature>
evnx completions bash
evnx completions zsh
evnx completions fish
evnx completions powershell
</CommandSignature>

---

## Supported shells

| Value | Notes |
|---|---|
| `bash` | Registers with `complete -F _evnx evnx` |
| `zsh` | Starts with `#compdef evnx`, so the file must be named `_evnx` and sit on `$fpath` |
| `fish` | A set of `complete` definitions plus helper functions |
| `powershell` | A `Register-ArgumentCompleter` script block |

Anything else is refused:

```bash
evnx completions elvish
# Unsupported shell: elvish
```

## Installing

### bash

```bash
evnx completions bash > ~/.local/share/bash-completion/completions/evnx
```

Create the directory first if it does not exist. For a quick test in the current
shell instead:

```bash
source <(evnx completions bash)
```

### zsh

The file **must** be called `_evnx` and live on `$fpath`:

```bash
evnx completions zsh > ~/.zfunc/_evnx
```

Then, in `~/.zshrc`, before `compinit` runs:

```bash
fpath=(~/.zfunc $fpath)
autoload -Uz compinit && compinit
```

<Callout type="info">
zsh caches completions. After replacing the file, run `rm -f ~/.zcompdump && compinit`
or start a new shell — otherwise you keep the old command list.
</Callout>

### fish

```bash
evnx completions fish > ~/.config/fish/completions/evnx.fish
```

fish picks this up automatically; no config change is needed.

### PowerShell

```powershell
evnx completions powershell | Out-String | Invoke-Expression
```

To make it permanent, append it to your profile:

```powershell
evnx completions powershell >> $PROFILE
```

## Exit codes

| Code | Meaning |
|---|---|
| `0` | The script was written to stdout |
| `1` | Unsupported shell — the message goes to **stderr**, and stdout stays empty |
| `2` | No shell argument given (argument-parsing error) |

<Callout type="warning">
**Check the exit code when you redirect.** `evnx completions notashell > out.sh`
leaves `out.sh` empty and writes the error to stderr, so a script that only looks
at the file sees a zero-byte completion rather than a failure. `set -e` or an
explicit `|| exit` covers it.
</Callout>

## The script matches your build, not the website

The completion script is generated from the command tree of **the binary you ran
it with**. That has one consequence worth knowing:

`cargo install evnx` compiles with default features, which do not include
`cloud`, `migrate` or `backup`. Completions generated by such a build will not
offer those commands, because that binary genuinely does not have them.

The prebuilt binaries — Homebrew, Scoop, winget, npm, PyPI and the GitHub
Release — are built with every feature enabled, so their completions cover the
full surface including `evnx vault` and `evnx cloud`.

<Callout type="info">
**Regenerate after upgrading.** The script is a snapshot, not a link. A build
that gained flags in a later release will not be reflected until you run
`evnx completions` again and replace the file.
</Callout>
